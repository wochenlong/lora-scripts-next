# Klein 训练任务选择器布局设计

## 背景

Klein 的“训练任务”目前由动态 Schema 表单渲染在数据集参数列表末尾。这样会让主控选择、数据集设置和训练参数混在一起，首屏层级不清晰；图像编辑模式下，用户还需要滚动到参数列表较后位置才能看到训练任务。

## 目标

- 将“训练任务”放在“训练目标”下面。
- 让训练任务继续作为主控选择的一部分，靠近基础模型、训练引擎和训练目标。
- 不改变 Schema 字段定义、条件判断、表单值更新、序列化结果或后端配置。
- 保留图像编辑模式下训练数据路径优先于训练任务的现有需求，但在新的主控区域内呈现。

## 方案

在 `DynamicSchemaForm.vue` 中将任务选择器从 Schema section 的字段渲染流程中独立出来：

1. 保留现有 `taskSelectorVisible`、`imageEditSelected` 和 `taskField` 逻辑。
2. 在动态字段 section 之前渲染任务选择器，使它紧接训练目标之后显示。
3. 从 section 内移除前后两处任务选择器渲染，避免重复显示。
4. 继续通过现有 `update()` 更新表单模型，任务选择器的选项和文案不变。
5. 通过布局样式让独立任务选择器与训练目标保持一致的间距和视觉层级。

不采用修改 Schema 字段顺序或使用 CSS `order`，因为这两种方式会把展示顺序和数据结构耦合，后续容易影响条件字段、目录定位和序列化。

## 测试

- 更新动态表单组件测试，验证双能力 Schema 下任务选择器存在，并位于训练目标对应区域之后、训练字段之前。
- 保留现有图像编辑模式任务选择和数据集路径测试，确认切换行为不变。
- 运行相关 Vitest、TypeScript 类型检查和生产构建。
- 启动本地页面，在 Klein 文生图和图像编辑两种模式下检查桌面布局。

## 范围

本次只调整 Klein/双能力 Schema 的训练任务布局，不处理此前提出的全局“支持项黑色加粗、不可支持项浅灰”的选择器改造；后者等 Klein 页面完成后再单独实施。
