# Roadmap / 产品路线图

[中文首页](../README-zh.md) · [English](../README.md) · [当前开发进展](dev-progress.md)

更新于 2026-10-01。以下是产品方向，不是发布日期、已完成清单或对上游全部能力的承诺。

## 持续主线

Next Trainer 的定位是多引擎专业训练工作台。3.x 持续扩大主流图像生成与图像编辑模型支持，同时打通数据准备、训练、监控和产物管理。

模型接入以 GUI、配置、运行环境、真实训练和产物验收为准，不能仅因上游支持或出现菜单入口就算完成。

## 3.2.0：数据集工作流

主线是把数据集管理、预处理、模型打标和标签编辑整合在同一工作区，不另做独立打标应用。

**已在 dev 集成的基础：**

- 可配置数据集根目录、自动发现文件夹及保留层级的上传。
- 冲突预检、上传重试、基础文件校验、异步概览。
- 单文件下载、整集 ZIP 导出、回收站与恢复。

**继续推进的范围：**

- 简单预处理，例如放大、透明背景转白底。
- 本地大模型自然语言打标，与 Tag 模型明确区分。
- 标签英文原词与中文释义对照。
- 完善管理、打标、编辑与训练间的路径和操作衔接。
- 常规模型支持更新，包括评估通过 Musubi 接入 Ideogram-4；须独立完成本仓适配与验收。

视频、音频管理以及 API 打标属于后续扩展，不因界面预留入口就列为首期已支持。发布准备时复查相关历史问题，记录风险与规避方式，不以清空所有历史 Issue 作为统一门槛。

## 3.3.0：AI Toolkit

完成 AI Toolkit 的产品化接入和验收，明确模型、训练模式、平台及配置边界。已有目录、安装入口或部分适配不等于此里程碑完成，也不承诺一次覆盖上游全部能力。

## 后续 3.x：具体版本待定

| 方向 | 用户价值与边界 |
| --- | --- |
| 引擎解耦 | 用户只安装所需引擎，可无引擎启动并选择默认引擎；Kohya 独立环境已集成，旧包迁移、依赖瘦身与完整无引擎验收仍需分开推进 |
| 可靠更新 | 明确应用、引擎、依赖的更新边界，保护用户数据，完善失败恢复 |
| EXE 客户端 | 简化启动和日常操作，不预设把全部 GPU 环境塞进单一 EXE |
| API 打标 | 在本地模型之外接入 API；明确费用、凭证、并发、重试与素材上传授权 |
| 产物发布 | 将训练结果发布到 ModelScope 或 Hugging Face；由用户配置授权，不默认公开上传 |
| 监控一体化 | 逐步融入 GUI；保留 TensorBoard 作为一种 Loss 查看方式 |

不将这些方向强行分配给 3.4.0、3.5.0 等版本，按成熟度与验收成本安排。

## 4.0.0：Agent 正式支持

让 Codex 等 Agent 能通过稳定接口完成训练集预处理、打标、标签编辑、训练和测试，而不只是增加聊天窗口。

需明确：GUI 与 Agent 共用业务规则，任务和产物可追踪，长任务可查询与取消，失败可恢复；覆盖、删除和对外发布等操作需要明确授权。协议与具体支持清单另行设计，不承诺所有引擎无人值守运行。
