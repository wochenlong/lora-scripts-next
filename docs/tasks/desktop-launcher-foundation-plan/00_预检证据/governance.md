# 测试、证据与变更治理（合并模板）

## 测试与证据治理

Unit验证路径/序列化；Contract验证catalog/registry/API字段与拒绝错误；Integration验证核心/IPC/资料根链路；Gray比较缺省旧行为与新profile、main与dev；Real验证真实EXE/下载/HTTP/联接；Zero-Short验证全新中文空格根。各目标和阶段必须覆盖六类，确实不适用时写具体替代。

新证据根为 `E:/OpenSourceTeamWork/workspace/tools/launcher-foundation-20261028/stageN/<case>/`。至少保存命令、EXE SHA256、catalog/commit、PATH/代理的非敏感范围、stdout/stderr、exit、时间、操作前后目录/registry哈希；真实服务补API JSON、HTML及资产响应、listener/Job归属、停止后进程端口。资料保留补源/目标联接和sentinel SHA256。用户资料只用人工构造测试值，不复制真实凭据。

| 资源 | 限额/预计用途 | 超限与清理 |
| --- | --- | --- |
| 新增磁盘 | 整轮硬上限8 GiB；包含两环境、缓存、工作副本与故障备份；每大步骤前检查增量 | 停止新操作、记录占用；不得删profile/失败证据来伪装达标 |
| 累计网络 | 整轮≤1 GiB，含重试；优先已校验缓存；两归档约95MiB，依赖冷下载可能是主体 | 记录已知下载字节/缓存命中；无法可靠计数标unknown并停止额外大下载 |
| GUI健康 | 每次≤180秒，先有限次循环轮询；不因输出PID延长 | 超时终止本Job，留日志与清理核验 |
| 安装子任务 | 单次建议≤1200秒；固定工具/源码下载≤600秒；同失败最多重试1次 | 不在无变化条件下无限重试；写failure |
| 测试进程 | 每个测试根独占；无GPU训练，无模型下载 | 完成、失败或关窗后均核Job/端口消失 |

Stage completion必须同时记录通过项、not-run/skip/unknown、残余风险与后继解锁。不以“测试总数通过”代替真实HTTP，不以旧原型代替新双版本。

## 失败报告模板

```text
Case / Stage / UTC时间 / EXE SHA256 / release commit：
前置状态与命令：
期望 → 实际（含exit和原始日志路径）：
分级：P0数据边界或核心不可用；P1主要链路/回退不可信；P2局部；P3文档体验。
影响：current/profile/受管进程/下载和磁盘增量：
已做清理与仍保留的现场：
根因证据 / unknown：
回退动作及唯一下一步：
```

P0/P1失败阻止涉及该条件的后继阶段。只允许在隔离根做可逆定位，不得以计划文档豁免真实资料保护。已授权操作遇到技术失败，先修复或留证，不无理由向用户加审批。

## 证据清理报告模板

```text
允许处理的绝对隔离根 / 所有权标记 / 是否含junction：
before：进程PID、listener、目录大小、下载累计：
停止：只停止此启动器的Job；验证所有子进程和端口已退出。
保留：summary JSON、stdout/stderr、哈希、截图、失败现场、profile sentinel、备份。
候选临时文件：逐路径列出；先核路径和联接目标，不递归穿过junction。
after：占用/残留进程/监听/未删除内容及原因：
```

本轮不自动回收大型测试根或备份；先产报告再决定后续清理。计划文档只写清理规则，不执行任意真实用户目录删除。

## 风险和授权治理

用户已授权底座实施与新根中的真实安装/修复/切换测试；无需额外批准才可运行这些已限定动作。允许读取官方公开归档和包索引；禁止消息发送、commit/push/issue写入、真实用户资料迁移、接管旧工作区、系统Python/全局代理改动、GPU训练/模型下载及对外发布。

只有范围或预算扩张、需要真实数据/对外写入、破坏不可逆资料等超出当前授权的情况才需先停止并说明来源。目录逃逸、未知marker/registry schema、签名/哈希不符必须拒绝变更，不能靠审批跳过校验。

## 变更控制治理

触发条件：新增目录映射/共享状态、profile schema改变、替换commit/配方、弱化验证/限额、扩展#516功能、发现原假设失败。先写 `CHANGE-日期-N` 至总控决策台账：原因、保留证据、替换范围、验收增量、授权来源；再同步manifest、目标、任务书、清单和goal。稳定阶段名不随意改；若必须改名，保留旧名→新名映射。

原型与失败证据不得删除或改写成成功。代码先行是历史事实，补计划不得倒签。状态升级必须有本轮证据，单一总控始终保留一个下一步动作。
