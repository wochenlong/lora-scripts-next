# 目标2：版本管理（versions）

回答的问题：真实main/dev能否并存并受控切换、回退、单项修复，而不破坏当前可用版本？

范围：immutable releases、独立GUI环境、current/previous_known_good、选择/回退/修复/删除保护、事务/registry恢复、Job和就绪。已有安装接管、启动器签名更新、精准引擎修复另行实施。

前置：G1清单合同与阶段1最小路径安全测试。后继：只有目标版本源码/环境/schema检查通过，才允许指针切换；只有真正健康后才记录known-good。

## 验收标准

1. 首次安装明确触发联网；打开窗口或inspect不隐式安装。新增另一发布不自动改变current。
2. main/dev各真实启动一次，API版本、HTML/JS/CSS与Job归属正常；两者都显示3.3.1-dev，以receipt/完整性/运行路径证明commit身份。
3. 已安装版本切换和回退不重新下载；失败不覆盖current；previous_known_good来自真实健康。
4. 当前版本和保留回退版本的删除被拒绝；允许移除的版本进入backup，profile保持不动。
5. source/GUI环境/基础Python按对应修复入口处理；损坏registry或未知schema拒绝写入，未完成事务可见，恢复不静默抹除状态。
6. 结束/失败/关窗后只回收本Job进程，端口消失；外部测试listener不受影响。
