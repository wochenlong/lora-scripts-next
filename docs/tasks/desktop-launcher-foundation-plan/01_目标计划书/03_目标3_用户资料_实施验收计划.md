# 目标3：用户资料（profiles）

回答的问题：代码/环境被切换或修复后，资料是否仍位于同一profile，且不同版本不会误读彼此队列/引擎/插件状态？

范围：schema 1 profile；共享user_data与library；版本compat；NEXT_TRAINER_DATA_ROOT/STATE_ROOT；旧发布run兼容视图。真实用户迁移、任意第三方硬编码写路径和跨版引擎环境复用不在范围内。

前置：固定映射与profile所有权边界冻结；最小junction真实探针通过才进入完整切换验收。后继：资料不变性是所有版本操作的硬约束，不是交付后再补的检查。

## 验收标准

1. 两env均接受绝对根，未设保持旧行为；显式feature路径优先；settings/凭据/预设/任务配置归档共享，队列等走STATE_ROOT。
2. 新Python接口有A→B→A持久化测试；正式旧发布通过run副本/junction读取相同目录，不向immutable app注入补丁。
3. 使用API写测试设置和预设、写library sentinel，记录哈希；切换、回退和源码恢复后内容/路径保持。不写真实密钥。
4. config/logs/.runtime/extensions/assets/toml等按release保留；shared library映射由管理层固定生成。迁移相对模型路径时显式预览/转绝对路径，本轮不自动改用户配置。
5. 拒绝未知根/联接逃逸；损坏源码修复和版本删除不移动profile。已存在用户内容不被默认文件覆盖。
