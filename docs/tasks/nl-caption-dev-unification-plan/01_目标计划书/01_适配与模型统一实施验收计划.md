# 适配、模型统一与完整验收实施设计

## T1：合并与开发基线

输入 feature 快照 `21571c5e`、dev分析快照`d9535c35`，开工重新fetch最新dev并冻结完整SHA。记录remote URL、双方HEAD、merge-base、dirty清单和备份hash。不要覆盖现有`branches/dev`或分析副本。

推荐在新临时集成worktree，从功能分支当前HEAD执行本地merge。保留这次计划文档及用户未提交修改，先仅提交本任务文档形成可追溯起点，再合并。冲突逐项登记双方行为、采用结果与验证，不整页ours/theirs。完成后快进`feat/NL-Captioning`，不强推、不改写历史。原worktree无关dirty若阻碍快进，先保存原字节/patch并验证备份，再进行仅该路径的可恢复处理；不得全量stash/reset。若与上游同文件变更不相容，保留两份、报告具体冲突，不能默默覆盖。

15处模拟冲突见预检；额外审查无冲突的ApiSettingsPage、通用user_data、自动导入和本地优先逻辑。client保留httpStatus和detail解析；proxy保留双方已有路由/下载行为，只做范围内兼容。记录纯dev带入与本任务主动改动的差别。

开发基线必须满足两个祖先检查、`git ls-files -u`为空、无冲突标记、前端typecheck/build、后端关键模块导入和Tag/Caption/设置最小HTTP冒烟。后续适配欠项记入U2/U3，不能将“能编译”写成全功能通过。输出固定merge SHA、冲突决策表、最小验证和未完事项。

## T2：可复用的本地模型

U1实测选型后形成唯一默认manifest：asset_id、模型系列、来源revision、每文件URL/bytes/SHA256、量化、mmproj类型、runtime版本/平台包、许可证、上下文/线程/非思考参数、语言与能力、内存建议、安装版本。

候选主模型和视觉组件必须来自匹配组合。当前纯文本0.8B没有mmproj，不能只改capability即称视觉可用。优先使用现有b11327；若真实兼容失败，最小升级并记录理由及新锁定版本，重跑所有受影响候选。最终只推荐一个默认，保留旧安装辨识与用户自行配置，不自动删除旧模型。

安装状态机：未安装→下载→校验→启动→text/vision探测→ready；错误/取消为明确非ready状态。重复点击不重复下载启动。断网、坏hash、截断、磁盘不足、端口冲突、启动失败可重试；部分文件不能注册。两页面共用同一asset/runtime/状态，停止后更新可用性，卸载或重试不触及其它模型。

一次用户安装操作应完成全部流程；不可让用户手工寻找mmproj或分别安装翻译模型。可用公开内置极小探测图片验证vision，不上传私有图片。CPU路径必测，GPU可用时补充，不能把GPU成功冒充普通CPU电脑保证。

## T3：配置、路由、预设、任务统一

### 配置与路由

以`mikazuki/llm`共享层为权威，`/settings/api`读写`/api/llm/*`。旧`/api/tag-translation/config`与其Profile字段通过适配迁移，不另存第二份权威配置。Profile包含稳定ID、endpoint/model、text/vision、语言、runtime引用、配置revision和运行时Key可用布尔。网络测试更新可用状态，单靠用户勾选vision不能替代实际能力测试；text-only允许翻译并拒绝打标。

路由依次选择具备请求能力且可用的远程Profile；失败/无可用远程且用户启用本地兜底才本地。未开启兜底时明确失败，不静默加载模型。前端local/API控件展示实际来源和策略，不建立优先本地的旁路；保留旧配置可读但将冲突策略显式迁移为remote-first并提示。Tag词典优先是Tag领域选择，不改变LLM请求内部的remote-first。

Key更新只进入后端运行时secret store；GET配置、导出、错误响应、SQLite快照、日志均脱敏。重启丢失运行时Key时标示需重新注入，不能显示假就绪。旧明文配置迁移不把Key复制到新的快照/备份；处理方式见授权治理。

### 预设

单一`user_data/presets`底层仓库，Caption用稳定kind/train_type隔离。规范字段包含`id/name/schema_version/template/system_prompt/language/output_format/max_length/model_capabilities/revision`和内置默认身份。dev的`config.prompt/language`、旧`/api/llm/prompt-presets`与localStorage导入都映射同一领域服务。通用PATCH必须走同样revision校验/原子保存，不能绕过Caption服务保护。

内置英文详细/简短与中文模板完整保留；既有其它语言不回退。预设是语言/详略/格式唯一控制，旧请求字段只作兼容规范化，冲突要拒绝/明确解释，不能让隐藏旧字段覆盖所选预设。试标、批量、缓存和重试使用同一最终配置与冻结revision。

迁移：脱敏快照→扫描旧来源→预览→显式导入→ID冲突重命名/用户选择→事务提交→验证数量/字段/hash→成功标记。版本标记幂等；中途失败保留源、撤销目标事务、重试不重复。执行者可在隔离复制数据上自主走完导入，不代替真实用户批准覆盖其数据。训练预设不读入Caption，两个API读写结果必须一致。

### 任务与文件

`caption_store`/SQLite保持执行权威，`task_bridge`向dev TaskManager与`user_data/tasks`投影一次；沿用maintenance lane，不新增执行器。冻结prompt/Profile身份/模型资产/输出策略后启动；不保存Key。重启恢复状态不自动再跑已完成项。

停止=协作取消且不写部分结果；隐藏=隐藏任务页投影；历史删除=仅明确档案/备份；回滚=before/after hash匹配后恢复标注。每种动作单独端到端测试；任何删历史不得删除图片或当前caption。并发保存、外部修改、重复点击、取消后晚到结果均受保护。

缓存按正文/图片hash、预设revision、模型/asset/runtime/config相关身份区分；切换模型、改提示词、改语言不能命中旧结果。错误语言/不合法JSON不能进成功cache。

## T4：新版前端闭环

### 打标页

采用dev全宽区/参数侧栏、ManagedDatasetPicker、方法/来源/分组模型、全局下载源；接回`/api/tagger/jobs`试标、批量、进度、取消、失败重试、报告与回滚。保留WD/CL参数、阈值/排序/输出，Tag请求不携带Caption字段。

Caption只列可用vision模型；API配置缺失链接全局设置，不显示可执行空入口。展示具体模型和下载/ready/故障状态，语言/长度按预设显示，不能恢复独立控制下拉。可编辑提示词、保存、另存为、恢复默认、切换时草稿保护；浏览器刷新后状态正确。预览不写盘；批量默认跳过已有，覆盖显式确认。

### 编辑页

服务端`caption_format/natural_text/caption_sha256`等来源字段恢复到DatasetItem。natural自动raw，Tag模式开关/拖拽/清理/排序/批量修改禁用；后端独立拒绝伪造调用。Tag的raw编辑不把格式改成natural。unknown/mixed使用安全策略，可解释原因，不猜测逗号即Tag。

展示完整自然语言正文；空scan草稿不覆盖磁盘文本，重入/重扫更新需保护未保存草稿。保存携带expected hash，冲突后允许检查与重新加载，不盲写。译文单独只读，英→中整句、中文正文直接短路；混合文本与语言不确定不误判中文，标点/数值/否定保留。切图、取消、改正文时清理过期响应，缓存必须绑定正文hash。

### 设置与任务页

全局设置唯一管理Profile/Key注入/本地安装，编辑与打标只引用同一状态。模型text/vision能力、英文支持和安装状态一致。LLM来源控件明确远程优先和本地兜底，不让旧local_only覆盖。任务页与打标页看到同一job，停止/隐藏/失败/重试可追踪。

桌面和390px宽浏览器均无横向遮挡，表单/侧栏/弹窗/长正文可操作；中英文文案、错误与加载状态完整。

## T5–T7：验证与交付

U4执行前端`npm run check`完整检查；后端先全仓收集、审查测试范围和依赖，再运行完整功能矩阵及共享模块回归。必须扩展`tools/run_caption_scope_tests.py`或替代清单以覆盖dev的`test_user_data*`、设置/proxy/任务/路径/迁移等，禁止仍以133项证明完整。范围外Agent真实接口与训练重任务不纳入本功能；全仓收集不能成为自动联系外部Agent API的授权。

真实远程和本地都必须跑预览→批量→磁盘→编辑→译文；mock用来模拟异常，不能代替真实链路。真实WD/CL旧Tag各至少一张、通过正式服务入口。Windows路径、junction/symlink以当前代码原用例验证；必要的Linux证据明确平台，不能用旧批准把Windows未验改成通过。

U5从固定candidate重新获取源码/依赖/模型，禁止旧sandbox缓存或硬链接。新根正式lifespan、生产前端、同一后端装载；完整前端与范围后端检查加真实HTTP/UI操作。若修代码产生新候选，旧候选失败证据保留，新根重跑最终从零门。

U6从验收通过的业务源码建立另一个新沙盒，独立配置/数据库/样本和日志，安装默认模型并启动应用。复用已验收资产仅允许物理复制并hash校验、来源入册，不与旧根共享可写路径或硬链接；此处不冒充第二次从零下载。交付PID/listener/HTTP/browser证据、启动/停止脚本、固定源码/资产锁、入口和重点手测单。Key未持久化导致重启需注入的行为明确说明；当前真实API测试仍必须已通过。
