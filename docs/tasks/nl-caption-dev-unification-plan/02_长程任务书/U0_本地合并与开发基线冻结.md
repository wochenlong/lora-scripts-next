1. 读取工作区规则和当前AGENTS，核对worktree/HEAD/status；为无关dirty文件保存原字节、patch和SHA。现有计划文档是本任务成果，仅显式路径纳入本地计划提交，禁止`git add .`混入用户测试。
2. 按GitHub代理规则fetch，记录开工最新dev SHA。与`d9535c35`不同则只补审新增差异，更新冲突清单后冻结，不无限追远端后续提交。
3. 建立本任务临时集成worktree，从当前feature提交本地merge冻结dev。按冲突清单逐项处理，前端采用新布局并保留功能安全契约；无冲突新模块同样审查。
4. 完成最小可构建/可导入修复，不提前下载探测模型。U2/U3的未完成适配写成明确任务，危险自动迁移先隔离，不接触真实用户状态。
5. 在临时集成根完成验证，创建merge/必要修复提交；保留用户dirty后非强制快进`feat/NL-Captioning`，核对HEAD及双祖先关系。若dirty与新基线冲突，停止此路径的覆盖并保留两份，继续独立工作。
6. 冻结`baseline.json`：原feature SHA、实际dev SHA、merge SHA、工具链、冲突决策、known gaps、用户修改hash。后续全部提交继承此基线。

## 失败退回

网络失败按既有每命令代理/必要OpenSSL处理；不得改全局git。编译/导入失败修复冲突后重跑相关最小验证。无法安全处理用户dirty只阻挡分支落位，不删除修改。AC-U0未通过不得进入U1。完成后更新canonical、保存压缩摘要、进入U1，无需逐阶段询问。
