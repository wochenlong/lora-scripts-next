目标T6；依赖AC-U4。目的：用没有旧运行产物的新根证明最终版本可安装、运行和真实完成任务。

## 执行步骤

1. 固定candidate commit/业务树hash/模型runtime锁。创建全新且不存在的`workspace/sandboxes/nl-caption-rebuild-<时间>-<run>/`；目录名仅为规则，不覆盖旧根。源码可由固定Git对象checkout，依赖/模型/运行产物不可复用。
2. 新Python/venv、新Node 22.17.1与npm依赖、新pip/npm/HF/model缓存、新配置、数据库、日志、公开样本，全部路径实际解析在该根内。无旧venv、node_modules、模型/runtime二进制或硬链接；新下载记录URL/bytes/SHA。
3. 审计并适配现有`download_caption_rebuild_inputs.py`、`serve_caption_acceptance.py`、`verify_caption_*`、`verify_managed_caption_runtime.py`的模型/语言/旧审批hardcode，保留新根校验与脱敏。通过产品一键安装入口装选定模型，不能脚本私拷绕过安装流程。
4. 在此根运行完整前端check、U4锁定后端矩阵；以正式lifespan与生产静态前端启动服务。记录工具链路径与依赖锁，监听地址仅回环，端口先检查不冲突。
5. 无Key启动→UI设置→一键安装→本地试标/批量→编辑/翻译→中文零请求；再后端运行时注入Key→真实remote-first→显式本地fallback故障测试。真实WD/CL、预设导入、任务取消/重试/回滚、重启状态也要通过。
6. 保存浏览器截图/网络和真实磁盘结果、进程/资源、依赖与资产下载证明；检查所有可写路径未污染用户环境。停止本阶段自有服务、确认端口释放，按清理治理处置大文件。

## 输出、验证与完成门 AC-U5

输出`rebuild-manifest.json`、下载/构建/测试报告、正式HTTP与浏览器验收报告、真实remote/local/Tag证据、隔离与清理记录。路径`docs/evidence/natural-language-captioning/dev-unification-20261010/U5/`。

必须是同一固定candidate的新根完整通过；工具链和资产均可追溯，所有运行状态独立。无Key启动不是remote测试通过；模拟端点不是实际服务；PID/文件存在不是健康证明。已完成其他阶段证据可以解释来源，不能替代本根真实运行。

## 失败退回

环境问题可在该根修安装步骤并保留首次失败记录；若业务代码/依赖锁/模型runtime改变，返回U4冻结新candidate，另建新根重跑最终从零门。禁止在失败根打业务补丁后宣称从零成功。清理受限可保留拥有清单且不再运行的本次根，记录原因，不绕过自动审批；不能借机删除旧用户沙盒。
