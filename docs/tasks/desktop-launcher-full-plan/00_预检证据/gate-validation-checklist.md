## 计划规则审查 GATE-00–GATE-14

下表是现行规则及检查依据；历史通过/失败保留原证据。本次仅修订文档，产品与资源状态不因规则更新而改判。

| Gate ID | 检查内容 | 依据与现行处理 |
| --- | --- | --- |
| GATE-00 | 来源与事实可信 | preflight-source-review、原始失败、当前分支/HEAD；不重开已完成 M0 探针 |
| GATE-01 | 计划、证据根和授权明确 | manifest、风险治理、既有 run 及用户 CR-006 指令 |
| GATE-02 | 总目标可交付 | A1–A10 功能范围保留；施工完成与最终验证分列 |
| GATE-03 | 顺序和保护明确 | M1–M5 连续施工→M6 集中验证；资料/信任/进程保护保持 |
| GATE-04 | 每阶段有具体产物 | 七份目标计划及任务书；不因精简测试删功能 |
| GATE-05 | 验证适量 | 施工编译/类型/最小回归与小夹具，综合实测留 M6；四引擎仅冒烟 |
| GATE-06 | 任务书可直接施工 | 稳定阶段名、Phase 输出/完成条件/失败处理；冲突调度已由 CR-006 替换 |
| GATE-07 | 完成与保存闭环 | 一次阶段基线保存；最终验收另列，不强制 C/S 两次推送 |
| GATE-08 | 开工清单只约束对应动作 | 核依赖、归属与资源；系统测试资源在 M6 对应专项前检查，不阻断 M5 编码 |
| GATE-09 | 证据状态真实 | pass/fail/not-run/blocked/skip 分开；快检不能冒充真实环境验证 |
| GATE-10 | 清理和预算不破坏现场 | 原硬预算、实际账本、受管根标记、保留原失败和外部资料 |
| GATE-11 | 高风险能力适时验证 | 实现时小夹具检查；M6 最少关键成功/拒绝/恢复分支；不重复原 VM/GPU 探针 |
| GATE-12 | Goal 与主计划一致 | v0.6 Goal 不含候选后暂停、单包单案锁或阶段间重新审批 |
| GATE-13 | 变更与权限可追踪 | CR-001–005 历史事实保留；未来调度以用户 CR-006 指令为准 |
| GATE-14 | 可以连续推进 | 用户已提出本次调整；不再索取一次同义审核，文档快检后交付主执行者 |

## 阶段施工与最终退出

| Gate ID | 当前事实 | 现行完成条件及后续动作 |
| --- | --- | --- |
| EXIT-M0 | done；原回执/边界见总控 | 保留已完成结论，不因新版规则重跑或伪改历史 |
| EXIT-M1 | in progress | 登记恢复等剩余施工完成、必要快速检查、一次基线保存；`final_validation=pending M6`，继续 M2 |
| EXIT-M2 | pending | RuntimeLayout/worker 与首批引擎功能齐备，小夹具冒烟、一次基线保存；真实引擎项 skip+CR-004，继续 M3 |
| EXIT-M3 | pending | 其余引擎与可信更新功能齐备，最少相关检查、一次基线保存；继续 M4 |
| EXIT-M4 | pending | 导入/冲突/路径及兼容回退功能齐备，小夹具、一次基线保存；真实综合链留 M6，继续 M5 |
| EXIT-M5 | pending | helper/独立壳/分发构建和中文材料齐备、必要快检、一次基线保存；缺干净 OS 不阻断施工退出，继续 M6 |
| EXIT-M6 | pending | 最终同包集中验证和最少关键保护检查，四引擎仅冒烟；修复后复验受影响链，最终统一报告/清理/基线回执 |

M1–M5 的 done 仅指施工完成和基线保存，不能解释为最终验收通过。一般实现/预检/harness 失败自主修复，不结束 Goal；网络故障保留保存待补状态并继续独立施工，交付前补核远端。只有新增必要授权、硬预算无法满足或无法隔离的真实资料/外部资源风险需要中断。

M6 干净 Windows/缺 WebView2 资源不足时只阻断对应系统专项，完成其余可执行沙盒链后统一列 blocked/not-run 和未证明内容；不把新目录称干净 OS，不把局部通过称全项通过。最终仍有核心功能缺陷时继续修复，不用“从简”替代施工完成。
