# 阶段施工完成与最终验证记录模板

适用 v0.6 / [CR-006](change-control-governance.md#cr-006连续施工完成后统一沙盒验证与汇报)。复用阶段现有记录即可，不必逐 Phase 生成独立报告。唯一进度写回[总控](../00_总控目标索引.md)；本模板不是已完成或已通过记录。

## 1. 最少身份

- 阶段稳定名、计划版本、run-id：待填。
- 实现范围、代码 commit/dirty 摘要：待填。
- 涉及实际包时的包路径/SHA、源码及 catalog/recipe 身份：待填；纯施工阶段未构建则注明。
- 必要快速检查命令、结果和已有输出位置：待填。

## 2. 两种状态分别填写

| 字段 | M1–M5 填写规则 | M6 填写规则 |
| --- | --- | --- |
| construction_status | pending / in progress / done；功能与必要快检完成才记 done | 核实全部施工产物齐备 |
| final_validation | `pending M6`；未运行实测不写 pass | 按实际案例逐项记 pass/fail/not-run/blocked/skip |
| baseline_status | 本阶段一次精确提交/push/远端核对及外部回执 | 最终基线与交付包身份分别记录 |
| remaining_boundary | 实测统一留 M6，原始失败和本阶段限制链接 | 系统资源缺口、CR-004 skip、核心问题与未证明能力 |

不要求 M1–M5 跑真实安装/全套矩阵、独立多轮审计或 C/S 两次推送后才继续。一般实现/测试脚本错误自主修复；只暂停有风险的具体写入，继续独立任务。

## 3. 施工完成核对

- [ ] 功能输出齐备，未把范围内能力删掉换成“测试略过”。
- [ ] 受影响编译/类型检查、最少回归或小夹具冒烟有实际结果，未重复无关全套检查。
- [ ] 路径/资料/信任/dirty/generation/lease/进程归属保护保持。
- [ ] 首次失败及必要现场留存；无关工作树/资料未改。
- [ ] 阶段状态与 final_validation 分列；按[Git 基线治理](git-baseline-governance.md)一次保存并核远端。
- [ ] 自动继续下一施工阶段；M5 后进入 M6，不要求用户再次审核或回复“继续”。

普通网络不可用时记录 baseline 待补，继续可做施工，交付前补推/核验；不能伪称已保存。新增必要权限、硬预算无法满足或无法隔离的真实风险才中断说明。

## 4. M6 集中验证追加

- [ ] M1–M5 施工与基线齐备，冻结最终 EXE/安装器/便携包及来源身份。
- [ ] 同包从零主流程及必要修复/恢复/回退/合成导入/更新/helper/退出保护结果集中记录。
- [ ] 四引擎只做入口、合成状态/RepairPlan、隔离与失败安全冒烟；真实安装/破坏修复、GPU/模型/训练/权重记 `skip + CR-004`，不宣称实机训练通过。
- [ ] A4/A8 同二进制测试与默认生产信任边界可核；资料/非目标哨兵及外部进程保留。
- [ ] 干净 Windows/缺 WebView2 专项有真实资源则执行；缺资源只记该专项 blocked/not-run，完成其余流程后统一说明，不冒称干净 OS。
- [ ] 修复后记录新包 SHA，只复验受影响链；保留原失败，不把“一次集中验证”解释为只许尝试一次。
- [ ] 汇总实际结果、未证明边界、原硬预算账本、清理与远端回执，最后统一完整汇报。

最终结论按事实区分“施工完成”“可执行沙盒验证结果”“系统专项受限”。必要项 fail/blocked/not-run 不填 pass；尚有核心功能缺陷不宣称全部完成。资源缺口不会触发重复候选/成本审批。
