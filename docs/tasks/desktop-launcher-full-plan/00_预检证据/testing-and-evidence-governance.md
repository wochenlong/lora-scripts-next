## 1. 测试时点与最小范围

| 时点 | 必要检查 | 推进方式 |
| --- | --- | --- |
| M1–M5 施工 | 受影响的编译/类型检查、最少相关回归；协议、路径或安全分支按需用小夹具冒烟 | 完成施工与快速检查，保存一次阶段基线后自动继续；不逐阶段原生实装、全套回归或六类测试齐跑 |

unit（单元）、contract（合同）、integration（集成）、gray（新旧对照）、real（真实入口）、Zero-Short（从零短验）是选取证据的方法，不是每阶段必须各跑一套的清单。复用与当前改动无关、身份仍有效的既有结果；不重复全组合故障矩阵、大目录全量哈希、多轮独审和同义报告。不得为了缩短流程绕过产品内的资料、路径、签名信任、dirty/generation、lease 或进程归属保护。

## 2. 施工完成与验收结论分开

M1–M5 的 `done` 表示功能施工和必要快检完成，并保存阶段基线；同时记录 `final_validation=pending M6`。中间未做原生/系统测试不能伪填 pass，也不形成等待用户审批的门。

单项结果使用 `pass/fail/not-run/blocked/unknown/not-applicable/skip`。真实引擎实测依据 CR-004 单列 skip，原 CR-001 失败/豁免事实保留；冒烟通过不能证明真实引擎或训练兼容性。M6 最终报告分别列施工完成、可执行沙盒结果、系统资源缺口和明确跳过项；缺干净 OS 不得宣称系统专项通过，但应完成其余施工和可执行链路后再统一交付。

一般实现、harness、预检、网络错误自行诊断修复，不因一次失败或自设尝试次数停止 Goal。发现真实资料/外部资源风险，只暂停有风险的具体操作并继续独立工作；新增必要授权、硬预算无法满足或无法隔离的真实风险才需要中断说明。未修复的核心功能缺陷不能以“测试从简”掩盖为完成。

## 3. 制品与最终沙盒

M0–M5 施工与基线齐备后，冻结最终交付包，记录 `trainer_source_commit / launcher_build_commit / catalog_digest / recipe_digest / package_sha256`。最终实际运行文件应来自 receipt 锁定的源码/资产，不能靠开发仓库 overlay 证明功能。

安装、运行、修复、导入、回退、可信更新和 helper 恢复使用可核对的最终包身份。修复导致包字节变化时记录新 SHA，只重跑受影响路径；影响范围无法判定时再扩大验证。一场集中验证允许修复和复验，不等于只能尝试一次。

A4/A8 的信任与 helper 核心验证使用同一交付二进制。显式沙盒会话可使用后端校验的只读受限测试配置，绑定新标记根、固定端点/公钥和内置动作白名单；普通根默认拒绝测试资产，生产信任不变。另 SHA 测试构建不能冒充最终包结果；缺生产身份/可审测试通路则该项如实 blocked，不自动公共发布或借用生产密钥。

## 4. 最少证据与保留

元证据根：`E:/OpenSourceTeamWork/workspace/tools/launcher-full-20261028/<run-id>/`；重型隔离根：`F:/NextTrainerLauncherSandbox/<run-id>/`。复用现有 run 和账本；新根须核绝对路径、卷及归属标记。本次文档修订不创建产品沙盒。

每个实际运行案例最少记录命令/参数、时间、代码/包身份、结果和必要原始输出；与判定有关的 `profile/instance/operation/case/host` 标识按需补充。不适用字段不强填，不为证据模板单独重跑产品。施工阶段以一份简短记录复用编译和夹具输出，最终以一份矩阵、一份报告和清理摘要交付。

原生主流程须有实际窗口/动作结果，服务须核对语义 API 和页面资源以及进程/监听器归属。修复/导入/helper 仅对目标控制文件、合成资料和非目标哨兵做必要前后比对，不对未变重型树反复全量哈希。退出只回收自有进程，外部同名程序/监听服务须保留。

保留首次失败、修复后的新 attempt、关键日志与必要现场摘要；不能覆盖失败或删除唯一证据后宣称可复现。Git 只存源码、锁文件和小型脱敏结果索引；模型、venv、缓存、VM 磁盘、凭据、真实资料和大日志不入库。清理只作用已核对的受管临时路径，不跟随 junction/symlink/reparse point，不碰外部资料。
