# 失败报告模板

> 文件：`<元证据>/<run-id>/<阶段>/<case>/<attempt>/failure-report.md`。首次失败不可被修复后覆盖；计划当前为drafting，本模板不代表发生过新运行失败。

## 1. 身份与阻断范围

- failure_id、发现UTC、阶段/用例/attempt：待填。
- 计划版本/规格摘要/代码commit/dirty摘要/包SHA/受限测试配置摘要及启用参数：待填。
- host/GPU/OS/运行根/recipe/model/dataset摘要：待填。
- 严重性：`P0 | P1 | P2 | P3`；类型：`preflight | contract | runtime | evidence | budget | authorization`。
- 结论：`fail | blocked | unknown`；阻止哪些动作/阶段：待填。
- 是否已停止相关任务，仍在运行的明确PID/归属：待填。

## 2. 期望、实际与原始证据

| 字段 | 内容 |
| --- | --- |
| 用户入口与期望 | 待填 |
| 最小复现命令/按钮与参数 | 待填；先脱敏凭据 |
| 原始stdout/stderr/退出码/耗时 | 待填链接 |
| 故障前后指针/receipt/registry/operation/实例generation | 待填链接 |
| 实际文件/解释器/锁/端口/进程树 | 待填链接 |
| 合成profile/非目标组件/外部sentinel摘要 | 待填链接 |
| 网络/GPU/空间/重试账本 | 待填链接；未知写unknown |
| 注入点与时间线 | 待填，不用“似乎失败”替代 |

## 3. 判断与安全处置

分开写已证实事实、待验证假设、可能根因和已排除原因。说明是否已越界、是否写入非目标路径、是否把dirty实例误标健康、是否产生不可信缓存或丢失回滚材料；不能凭异常文本直接重装全部。

签名/helper失败注明是否最终同一二进制、受限测试配置是否仅新标记沙盒生效、默认生产根/模式是否保持；另SHA测试构建成功不能覆盖最终包A4/A8失败。缺可审核同制品测试通路及生产资源时明确blocked。

先保全命令/日志/状态/目录清单与关键哈希，再停止本任务自有进程；不按进程名杀其他程序。声明允许的最小修复计划、保留路径、是否需资源/范围变更以及恢复验证器。无法证明精确恢复时维持dirty/blocked，不能仅以进程退出或状态字段改写宣布恢复。

## 4. 修复与复验记录

| 新attempt | 代码/包身份 | 修复动作与影响范围 | 复验命令/实际结果 | 证据 |
| --- | --- | --- | --- | --- |
| 待填 | 待填 | 待填 | not-run | 待填 |

如重建包SHA发生变化，列出M6受影响用例和重跑结果；影响不明全跑。记录同引擎真实短训练失败重试累计，超过2次或总预算不足时停止相关真实任务并走变更，不改用更弱模型冒充通过。故意故障注入/中断恢复不计该次数，但所有消耗仍计入总预算。

## 5. 清理、授权与交接

列出保留的raw日志、故障元数据、最小复现夹具及大现场的位置/大小/摘要。清理需要[清理报告](evidence-cleanup-report-template.md)，不得沿联接删除；若删除大现场，明确不可再读取原字节的限制。引用授权/变更记录；唯一下一步必须具体且为单项。总控更新为对应pending/blocked，不能修改旧底座计划的历史完成状态。
