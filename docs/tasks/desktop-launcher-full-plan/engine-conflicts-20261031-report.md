# CR-015：按目标引擎管理运行与变更冲突

状态：complete-with-boundary（本轮约定范围）。来源为用户明确批准“目标引擎训练、被占用或已有安装修复任务时限制修改；只读检查、计划预览和无冲突独立安装允许网页服务继续运行”。采用现有施工计划的功能返修路径，BDD（按使用流程验收）与并发锁定向测试；不新增审批门。

## 原因与决定

原 `.launcher-lock` 从服务启动独占至服务停止，Rust 入口还显式拒绝服务运行时操作。这是实现限制，#516 未要求。上一轮停止服务提示没有解决锁范围问题，本轮替代该流程，历史记录保留。

三层跨进程协议：`.launcher-lock` 全局生命周期门，服务及引擎操作共享、主程序变更独占；`.launcher-state-lock` 保护 registry/组合绑定短事务；`state/engine-locks/<engine>.lock` 跨发布按目标引擎保护，训练/主动训练预检共享使用、安装/修复/恢复/执行探测独占修改。Windows 与 Python/Rust 统一锁第一个字节，系统释放退出进程所持锁。只读检查与计划不持目标引擎锁。

训练排队期间不占环境；执行前重新核对实例与代次，避免排队命令使用已改变的绑定。冲突由实际锁取得判断，界面状态只用于提示。旧训练器没有此协议时不能凭新壳放开保护；新候选必须固定包含新 Python 实现的已推送源码，不能覆盖旧安装源码或借开发目录叠加验证。

共享 registry 的长操作只在提交短事务时独占，并重新读取最新状态，防止不同引擎或服务健康登记覆盖彼此。桌面长操作维持单任务串行；只读入口不再被运行服务及该长操作的 Engine mutex 阻塞。
