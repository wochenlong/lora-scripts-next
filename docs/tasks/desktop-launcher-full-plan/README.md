# 桌面启动器完整交付施工计划

本计划把 [#516](https://github.com/wochenlong/lora-scripts-next/issues/516) 和[后续设计书](../../design/desktop-launcher-next-design.md)转成 M0–M6 的长程任务。用户在审计稿交付后于2026-10-28明确指令“建立goal目标，开始执行任务书的任务”，现已建立实际Goal并进入M0；预算和非发布边界继续生效。下文阶段文档保留0.1起草时的假设和not-run快照，实时授权/阶段状态以总控为准。

- 唯一执行进度：[00_总控目标索引](00_总控目标索引.md)。任务书、报告、manifest 都引用它，不另维护一套完成状态。
- 快速审核：[用户审计单](07_用户审计单.md)，包含待审决策、资源预算、沙盒要求和开工边界。
- 分阶段施工：[目标索引](01_目标计划书/00_目标计划书索引.md)、`02_长程任务书/`、`04_阶段开工清单/`。
- 全程提示词：[桌面启动器全程执行 Goal](03_goal提示词/桌面启动器全程执行_goal提示词.md)，当前为待审草稿；批准后先进入 M0，满足门禁后继续各阶段。
- 审查与治理：[manifest](plan-manifest.md)、[开工复盘](06_开工前最终复盘报告.md)、[证据入口](00_预检证据/README.md)。

本计划是历史[底座计划](../desktop-launcher-foundation-plan/00_总控目标索引.md)之外的后续工程，保留底座已经完成的事实。后续设计书仍是唯一规格；本目录负责施工、验收和执行进度。本计划新增用户指定的 M6 最终复验，不改变原 M0–M5 的设计含义。

所有阶段通过验收后，必须提交并普通 push 到 `origin/feat/desktop-launcher`，远端完整提交核对成功才算保存基线。用户批准计划并启动执行后，这些阶段推送属于已有授权，无需逐阶段重复申请。合并、正式发布和给他人发送消息另属范围。

本轮只验证文档结构、链接、阶段一致性和原工作树保护，不把历史产品测试结果当作本轮重跑结果。`python scripts/validate_plan.py` 可在本目录复核静态结构；执行阶段仍须完成各任务书要求的真实验收。
