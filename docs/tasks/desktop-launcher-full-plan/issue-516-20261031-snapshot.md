# feat(launcher): 独立桌面启动器 — 解决分发、版本管理与环境修复

来源：https://github.com/wochenlong/lora-scripts-next/issues/516

Issue更新时间：2026-10-28T09:59:30Z

## 背景与定位

当前训练器的分发与升级完全依赖整合包：用户下载几 GB 的压缩包、解压、覆盖更新。由此产生的问题在 issue 里已经反复出现：

- #500 整合包更新会丢失 / 破坏 Kohya，依赖下载卡死
- #470 更新后 Kohya 引擎提示未安装，且重装失败
- #489 环境异常有提示但没有可见的「修复」入口
- #459 实体环境存在但状态文件缺失，错误显示「未安装」

这些都不是单个引擎的 bug，而是**缺少一个独立于训练器本体的管理层**。整合包一旦损坏，用户没有任何可自助恢复的手段，只能重新下载整包。

因此计划做一个**独立的桌面启动器**，定位是训练器的分发与运维入口，解决三件事：

1. **分发** — 用户只下载一个轻量启动器，由它完成训练器的下载与部署，不再分发 GB 级整合包
2. **版本管理** — 自助更新；当前版本有问题可回退到旧版本；支持在 `main`（稳定）与开发分支之间切换
3. **环境管理** — 检测并修复训练器本体环境，以及各训练引擎（Kohya / AI Toolkit / DiffSynth / Anima Fast 等）的安装状态

启动器是**独立进程**，不随训练器一起被覆盖更新——这是它能充当恢复手段的前提。

## 功能范围

侧栏只有三项，不要把训练器自身的功能（数据集、模型训练、标签编辑）搬进启动器——那些是被启动程序的职责，放进来会让用户点进去却无法操作。

### 1. 启动（含安装训练器）

核心是**主按钮随状态变化**，而不是一个固定的「启动」按钮：

| 状态 | 主按钮 | 辅助信息 |
| --- | --- | --- |
| 未安装 | 安装训练器 | 下载体积、目标安装路径、可改路径 |
| 已安装 · 环境正常 | 启动训练器 | 绿点 + 当前版本号 |
| 已安装 · 有新版本 | 启动训练器 | 次级按钮「更新到 vX.Y.Z」，**不阻塞启动** |
| 已安装 · 环境异常 | 去环境管理 | 红点 + 直接写明缺什么（如「未检测到 CUDA」） |

**首次使用是最重要的状态**：用户可能只拿到了启动器，本机什么都没有。这种情况下首屏应当直接呈现为安装引导（显示将要下载什么、装到哪、占多大），不要让用户先看到「启动」再自己发现需要安装。

安装过程需要有明确进度（下载 / 解压 / 装依赖分阶段），失败可重试且不留下半损坏状态。

### 2. 版本管理

- 列表展示：版本号、发布日期、占用空间、状态（当前 / 已下载 / 可下载）
- 操作：切换、下载、删除
- **回退**：保留至少上一个可用版本，当前版本出问题可一键切回
- **分支切换**：`main` 稳定线与开发线分开展示，切到开发线需要明确提示风险
- 多版本可共存，切换不应触发重新下载

### 3. 环境管理

逐项检查 + 单项修复，这是解决 #500 / #470 / #489 的关键：

- 训练器本体：Python 版本、虚拟环境完整性、依赖一致性
- 各训练引擎独立检查：Kohya / AI Toolkit / DiffSynth / Anima Fast 等，分别显示已安装 / 未安装 / 损坏
- 硬件与系统：CUDA 版本、显卡型号与显存、磁盘剩余空间
- 每个检查项有明确结论（✓ / ✗）与**可点击的「修复」按钮**，不能只报错不给出路
- 修复必须**对症**：只重装缺失或损坏的部分，禁止默认整包重装（见 #462）
- 需要处理「实体环境存在但状态文件丢失」的情况（见 #459），以实际文件为准而非仅看状态文件

## 设计约定

视觉上走简约工程风格，参考 Codex / 现代开发者工具，**不要二次元元素**：

- 中性灰阶：背景 `#fff`，侧栏 `#fafafa`，边框 `#e5e7eb`，正文 `#1a1a1a`，次级文字 `#6b7280`
- 主按钮用 `#1a1a1a` 填充 + 白字，不用彩色主按钮
- 彩色仅用于状态指示：绿色正常 / 琥珀色有更新 / 红色异常
- 1px 实线分隔，不堆叠阴影与圆角卡片
- 版本号、路径、CUDA 版本、显存等技术信息用等宽字体
- 侧栏宽度 180–200px，图标单色描边，激活态用浅灰填充
- 窗口默认 900×600 左右，不要用大窗口再靠插画填空白
- 首屏不需要产品宣传语，只回答「装了没有、什么版本、环境行不行、能不能启动」

## 技术选型（待讨论）

启动器体积要小、能独立运行、不依赖训练器环境。倾向 Tauri 或 Electron，也可以是 .NET / PySide6 单文件打包，认领后可以先提方案再动手。

关键约束：
- 启动器与训练器完全解耦，训练器更新不影响启动器自身
- 启动器需要能在训练器完全损坏的情况下正常运行并实施修复
- Windows 优先（当前用户主要在 Windows），其他平台后续考虑
