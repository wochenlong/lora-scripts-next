## 2. 建议资源预算（批准后生效）

| 项目 | 建议上限与限制 |
| --- | --- |
| 下载 | 全计划新增网络总量≤200GiB，模型/依赖/VM镜像及重试都计入；仅合法固定资产清单 |
| 大资产磁盘 | F盘独立沙盒峰值≤300GiB，实时保留≥100GiB空闲；不在E盘重复放模型/VM |
| 元证据 | E盘本任务新增≤5GiB，保留≥20GiB空闲；超大原始资产记录身份并放F盘 |
| GPU | 全计划≤180分钟；同一时刻1个任务；每次短训练≤20 optimizer steps或10分钟，取先到者，须产出可加载权重；每引擎全计划训练失败重试≤2次，均计总预算；故意故障注入单列 |
| 隔离 | 拟使用`F:/NextTrainerLauncherSandbox/<run-id>/`；本轮未创建。只操作本任务新建目录与合成/许可数据，不迁移真实用户资料 |

这是上限提案，不代表200GiB一定够，也不承诺本机16GiB显存能运行所有引擎的可验收模型。M0先按合法资产清单估算并做最小探针；不足时给出实际差额和最小资源请求，不能静默提高预算或删掉训练验收。详细规则见[资源与授权](00_预检证据/risk-and-authorization-governance.md)。

## 3. 最终“从零”如何判定

1. **干净Windows轨**：新OS/干净快照或等效独立测试机，记录起始软件清单；没有Python/uv/训练器/开发缓存，覆盖缺WebView2。只带最终交付包、合法数据和明确网络配置，通过普通用户真实界面安装并验证网页资源与API。
2. **GPU轨**：独立新根/独立缓存，由同一最终包从零安装四引擎，各自完成导入、GPU运算、最小训练和权重检查。若干净OS不具备CUDA，使用单独GPU Windows环境，清楚列联合矩阵，不能声称它是同一干净系统上的GPU验收。
3. 最终包SHA固定。用M2/M3已有环境训练或隐藏PATH不能替代M6；缺资源、skip、unknown都不能算最终完成。VM、模型、缓存与训练预算在M0前置核查。
4. 实际下载并安装的训练器源码必须包含本功能改动：从已推送的完整feature提交生成并锁定候选归档，记录训练器源码提交与启动器构建提交。不能安装旧main/dev后借开发仓库文件抵扣新功能验收，也不能把测试候选默认宣传成稳定main。

## 4. 分发与签名边界

本计划要求把可信清单、壳更新和故障回退**实现并实测**。最终包可通过同一二进制的显式受限测试配置，在新建且有标记的独立沙盒验证测试信任链；默认生产信任根不变，普通根拒绝测试资产，配置摘要进入证据，不能开放任意URL/命令执行。测试签名不等于维护者生产签名，普通用户包不得默认信任测试根。

另行编译、SHA不同的测试版只能补协议证据，不能抵扣最终包A4/A8。若没有可审安全测试通路且没有生产签名资源，这两项仍blocked，不能称全部完成。M3/M5在实现时必须提前解决该验证入口，不能等M6用不同包替代。

维护者尚未配置生产签名身份/渠道时，交付维持内置清单与手动升级，按D5推荐的保守路径标注真实状态；生产自动更新上线保持未完成发布项。若审核要求“本次必须生产渠道上线”，则把维护者签名/渠道资源提升为M0必须提供的硬前置。公共发布、合并、给他人发送消息不在本次自动执行范围。
