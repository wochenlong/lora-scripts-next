## 目标（Goal）

开发全部完成后，用同一最终交付包在真实干净Windows OS/VM和无开发缓存的独立GPU根联合完成A1–A10，并重新从零安装Kohya、Anima Fast、AI Toolkit、DiffSynth，逐引擎真实训练并验证权重；保留完整证据后提交/push最终基线。

## 范围与约束（Scope and constraints）

必读[目标M6](../01_目标计划书/07_目标M6_从零沙盒最终验收_实施验收计划.md)、[开工清单](../04_阶段开工清单/阶段M6_从零沙盒最终验收_执行前清单.md)、[测试证据](../00_预检证据/testing-and-evidence-governance.md)、[授权](../00_预检证据/risk-and-authorization-governance.md)、[Git治理](../00_预检证据/git-baseline-governance.md)。M0–M5完成门及push回执先齐备。本轮不执行以下任何Phase。

两轨合同固定：C为真实干净Windows OS/VM，必须证明无Python/uv/训练器/缓存且缺WebView2；G为新run-id、所有开发环境与缓存独立的GPU根。Windows Sandbox GPU显示能力不等于CUDA；若分机测试，明确联合矩阵，不称同一干净OS GPU验收。单纯限制PATH或清空目录不能替代C。

资源拟M6网络≤60GiB、GPU≤90分钟且不得超过总余额；全计划网络≤200GiB、GPU≤180分钟。F峰值≤300GiB且余≥100GiB，E新增≤5GiB且余≥20GiB；每次最多20 optimizer steps或10分钟先到即止、同时1GPU任务，同引擎真实短训练失败重试全计划≤2次。故意故障注入/中断恢复不计该次数，其资源仍入总账。模型/数据许可、摘要和预算M0先锁定；必要模型不适合16G则阻塞，不偷换验收或借远端资源。

## 执行阶段（Execution phases）

### Phase 6.1：冻结制品与重建两轨基线

- Purpose（目的）：证明测的是最终包，且M6资源真正独立于开发缓存。
- Outputs（产物）：`identity.json`、C的OS/快照/缺组件证明、G的解释器/缓存归属清单、包SHA及资源余额；分别记录trainer_source_commit、launcher_build_commit、catalog/recipe_digest，后续纯状态S提交不改写包构建身份。
- Completion criteria（完成标准）：M0–M5门通过；无未解P0/P1；C/G可用；最终候选包固定；测试数据只有合法小数据/合成资料。
- Validation（验证）：采集OS/已装包/注册表/文件及进程环境，检查Python/uv/WebView2实际缺失，审查缓存解析路径；G不引用宿主开发venv/缓存；实际run的worker/路径/引擎模块来自receipt锁定且包含feature改动的源码归档，禁止旧main/dev加开发仓库overlay/PYTHONPATH借用；核对F/E余量及包哈希。
- Evidence（证据）：`<元证据>/<run-id>/M6/00-baseline/`，重型镜像/根在F。
- Failure handling（失败处理）：缺OS/镜像权利/缺WebView2条件/显存或预算时写preflight失败报告并阻塞，不把PATH测试当基线通过。

### Phase 6.2：干净Windows安装与恢复矩阵

- Purpose：从普通用户入口验证A1、A2、A3、A4、A7、A8、A9、A10的非GPU链路。
- Outputs：逐case操作录像或关键截图、HTTP语义结果、操作/receipt/registry快照、资料/缓存摘要、更新helper和进程记录。
- Completion criteria：900×600三页可实际操作；缺WebView2有安装/离线引导；无系统Python/uv也能真实GUI启动；网络/磁盘/提交中断恢复不污染旧绑定；签名/历史/离线回退/壳更新/合成迁移按A矩阵通过。
- Validation：安装器与便携包入口、中文空格路径、真实按钮与API/HTML/JS/CSS；本地HTTP注入200/错206/416/ETag变化；代理失败不直连；受限虚拟卷模拟空间不足；四阶段取消/关窗/强退后重启；壳占用/替换/首启/schema故障恢复精确字节；迁移冲突/源变化/相对外部路径；同名外部程序/HTTP哨兵保持存活。
- Evidence：`M6/C-clean-windows/<case-id>/<attempt>/`；矩阵每条指向raw与包SHA。
- Failure handling：保留首次失败，不覆盖；修复后新包SHA绑定新attempt并重跑受影响链路；无法识别影响范围全跑M6。

签名/远端及helper恢复必须由最终同一交付包/二进制SHA实测A4/A8。同一二进制可读取仅新标记沙盒显式启用的只读受限测试配置，配置摘要/参数入证据，包字节和默认生产根不变；配置只能选沙盒测试根/源，动作限内置ID且资产验签验哈希，不能执行任意URL/命令，也不能作用真实/既有非测试根。默认模式另测拒绝测试根/测试receipt/未授权覆盖。

另SHA测试构建仅补协议证据，不能抵扣A4/A8。若最终包无可审核受限通路且无生产资源，A4/A8保持blocked、M6不完成。D5普通默认包可内置清单+手动升级，生产渠道不自动上线，该边界不豁免最终包矩阵。

### Phase 6.3：四引擎独立从零安装与分层验收

- Purpose：在G轨证明A6及GUI健康与引擎可训练相互独立。
- Outputs：四份固定配方/解释器/依赖/上游/补丁身份、安装与import日志、GPU张量、真实短训练日志/权重/读取报告。
- Completion criteria：四引擎均由同最终包控制从零下载和安装，未复用M2/M3安装或缓存；结构/导入/GPU/训练分别pass；权重非空且格式可读，步骤与耗时在限额内。
- Validation：按Kohya→Anima Fast→AI Toolkit→DiffSynth串行取得GPU lease；安装后核对版本与关键import及实际入口；使用M0固定小模型/数据，配置预算内checkpoint；记录真实optimizer step、峰值显存、退出码、权重SHA与读取后的键/shape/dtype/有限值。20步/10分钟先到，若尚未有有效权重则失败而非伪造通过。
- Evidence：`M6/G-gpu/<engine-id>/<install|import|gpu|train>/<attempt>/`；大权重留F并登记摘要/保留位置。
- Failure handling：累计真实短训练失败后的重试（同引擎全计划最多2次；故意故障注入/中断恢复只计资源），GPU/网络余额不足即停；不得临时替换弱模型、缩减引擎数或把GPU张量算训练成功。
