## 执行阶段（Execution phases）

### Phase 6.1：冻结制品与建立C及冒烟基线

- Purpose（目的）：证明测的是最终包，且GUI从零条件与四引擎小夹具边界明确。
- Outputs（产物）：identity.json 记录新根/主机、包 SHA、源码/catalog/recipe 身份、小夹具和预算；有干净 OS 系统资源时另记真实缺组件基线，缺资源保留 blocked/not-run，不阻断其余案例。
- Completion criteria（完成标准）：M0–M5 施工及基线齐备，最终包固定，新独立根/四引擎夹具可用；只用合法工具和合成资料。系统资源缺口只阻断对应专项，无 GPU/模型前置。
- Validation（验证）：核最终包模块/receipt 与源码身份、小夹具允许路径、非目标哨兵及 F/E 余量；对实际具备的干净 OS 专项采集缺 Python/uv/WebView2 证据，缺资源记录真实边界，不靠开发仓库 overlay 或限制 PATH 冒充。
- Evidence（证据）：`<元证据>/<run-id>/M6/00-baseline/`，重型镜像/根在F。
- Failure handling（失败处理）：缺OS/镜像权利/缺WebView2条件或必要预算时沿用preflight失败记录阻塞对应门，不把PATH测试当基线通过；GPU/显存/模型缺失不再阻塞。

### Phase 6.2：集中沙盒安装与必要恢复，系统专项按资源执行

- Purpose：从普通用户入口验证最终包主流程及最少关键保护；干净 OS/缺 WebView2 专项只在有真实合法资源时执行。
- Outputs：逐case操作录像或关键截图、HTTP语义结果、操作/receipt/registry快照、资料/缓存摘要、更新helper和进程记录。
- Completion criteria：900×600 三页操作、实际安装/启动/API/页面资源/停止及选定恢复路径有真实结果；系统专项具备资源时验证缺组件引导，缺资源该项 blocked/not-run，不把新根通过当干净 OS 通过。
- Validation：最终同包安装器/便携入口、中文空格路径、真实按钮与API/HTML/JS/CSS仍须验证；其余按影响选下载/信任/取消恢复/壳更新/合成迁移的少量关键成功、拒绝、恢复分支，复用有效证据；保留资料精确字节和同名外部程序/HTTP哨兵保护，不重复全套矩阵。
- Evidence：`M6/C-clean-windows/<case-id>/<attempt>/`；矩阵每条指向raw与包SHA。
- Failure handling：保留首次失败，不覆盖；修复后新包SHA绑定新attempt并补受影响必要链路；影响不明先诊断明确边界，不默认全套重复。

签名/远端及helper恢复必须由最终同一交付包/二进制SHA实测A4/A8。同一二进制可读取仅新标记沙盒显式启用的只读受限测试配置，配置摘要/参数入证据，包字节和默认生产根不变；配置只能选沙盒测试根/源，动作限内置ID且资产验签验哈希，不能执行任意URL/命令，也不能作用真实/既有非测试根。默认模式另测拒绝测试根/测试receipt/未授权覆盖。

另 SHA 测试构建只补协议证据，不能抵扣最终 A4/A8；缺同包可审通路且无生产资源时，记录对应 blocked 并继续其余可执行链，最终不能称该项通过。D5 内置清单+手动升级不授权生产发布或取消信任保护。

### Phase 6.3：最终包四引擎独立控制冒烟

- Purpose：用最终同一交付包核对A6四引擎独立检查/诊断、RepairPlan、修复与隔离控制合同。
- Outputs：四份固定配方/解释器/依赖/上游/补丁身份、小夹具状态/计划与必要冒烟结果，真实验证跳过项写入既有矩阵。
- Completion criteria：四引擎检查/修复入口各自可调用，以合成/小夹具核对独立状态、RepairPlan及必要成功/拒绝/恢复分支；路径/运行时隔离、dirty/generation、lease和失败拒写有效，非目标摘要不变。
- Validation：按Kohya→Anima Fast→AI Toolkit→DiffSynth调用各入口，核对配方/实例路径与最小修复计划；每引擎选择必要成功分支，关键拒绝/恢复分支按影响复用有效证据。真实安装/导入、破坏真实环境修复/再训练、GPU小张量、完整模型加载/最小反向、短训练/步数/loss/显存、权重读取/键/shape/dtype/有限值均 `skip + CR-004`，不产生真实验证pass。
- Evidence：沿用 `M6/acceptance-matrix.json` 记录逐引擎原始输出、目标/非目标摘要及CR-004；附件放 `M6/smoke/<engine-id>/<attempt>/`，不新增报告。
- Failure handling：入口/计划/隔离或失败保护不符合合同仍阻塞对应门，保留首次失败；GPU/模型/训练资源缺失不阻塞，不缩减四引擎实现范围。

### Phase 6.4：必要恢复、互不干扰与退出复验

- Purpose：证明A2/A5/A7/A9/A10的精准修复和保护在最终包上实际成立。
- Outputs：沿用GUI必要恢复与四引擎冒烟矩阵，记录固定RepairPlan、前后树摘要、generation/dirty、引用闭包及恢复/退出原始证据。
- Completion criteria：GUI本体保留必要成功/拒绝/恢复证据；四引擎仅小夹具独立冒烟，不做真实环境破坏修复；最小修复不改变非目标环境/资料，包已改未提交不误标健康；不要求重复所有故障矩阵。
- Validation：受管副本/快照中按影响选必要登记/单包/源码/Python恢复，复用有效证据；四引擎复用6.3小夹具结果，核对只读摘要、dirty/generation、lease、失败拒写及少量恢复分支；维护/训练lease存在时拒切换/删除/run重建可用合成状态验证，不启动训练。最终关窗检测Job/端口消失且外部同名进程/HTTP服务不变。
- Evidence：`M6/faults/<component>/<fault>/<attempt>/`、`M6/exit/`；不跟随联接计算外部路径变更。
- Failure handling：发现非目标变化/误杀/越界即P0停止，保留原始快照和日志；不能直接整包重装抹除现场，不删除真实资料。

### Phase 6.5：同制品结案、清理与远端基线

- Purpose：让最终完成可以由第三方复查，并保存真实开发基线。
- Outputs：A1–A10展开矩阵、`final-report.md`、`delivery-manifest.json`、资源账本、清理报告、EXIT-M6、M6提交/push回执。
- Completion criteria：全部施工齐备；最终包可执行主流程和四引擎冒烟有结果，发现核心功能缺陷自主修复后只补受影响链；系统资源缺口 blocked/not-run、真实引擎/GPU/训练 skip+CR-004 单列。最终包/中文材料/许可及远端回执可核，最终报告区分施工完成、沙盒结果与系统专项未验证，不冒称全项通过。
- Validation：一次定向核对最终矩阵/原始证据、包身份及基线；精确暂存/普通 push/远端 SHA 核验，按清理预览仅处理受管临时物，核必要资料哨兵与外部服务；不多轮独审或重复全树哈希。
- Evidence：`M6/final-report.md`、`M6/acceptance-matrix.json`、`M6/cleanup-report.md`、`M6/stage-completion.md`、`M6/git-baseline/`。
- Failure handling：一般产品或脚本错误自主修复并补受影响路径，不结束 Goal；网络失败继续诊断，不能伪称已保存。缺系统资源完成其余链后统一报告边界；有核心缺陷不宣称施工全部完成，公共发布另行授权。
