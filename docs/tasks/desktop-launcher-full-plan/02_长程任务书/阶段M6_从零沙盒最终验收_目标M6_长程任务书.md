- Purpose（目的）：证明测的是最终包，且GUI从零条件与四引擎小夹具边界明确。
- Outputs（产物）：沿用`identity.json`记录C的OS/快照/缺组件证明、四引擎冒烟根/配方绑定、包SHA及必要资源余额；分别记录trainer_source_commit、launcher_build_commit、catalog/recipe_digest，后续纯状态S提交不改写包构建身份。
- Completion criteria（完成标准）：用户后续审核本批范围且M0–M5门通过；无未解P0/P1；C及四引擎小夹具可用；最终候选包固定；仅合法工具/合成资料，不要求GPU/模型。
- Validation（验证）：采集OS/已装包/注册表/文件及进程环境，检查Python/uv/WebView2实际缺失；核对最终包worker/路径实现与receipt候选归档身份，禁止旧main/dev加开发仓库overlay冒充交付；核对小夹具允许路径、非目标摘要、所需F/E余量及包哈希。
- Evidence（证据）：`<元证据>/<run-id>/M6/00-baseline/`，重型镜像/根在F。
- Failure handling（失败处理）：缺OS/镜像权利/缺WebView2条件或必要预算时沿用preflight失败记录阻塞对应门，不把PATH测试当基线通过；GPU/显存/模型缺失不再阻塞。
