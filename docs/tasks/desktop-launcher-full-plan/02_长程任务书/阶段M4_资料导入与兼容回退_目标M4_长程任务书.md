## 目标

通过可预览、可中断、可恢复的资料导入，让旧安装继续可用；让新旧发布切换携带正确 profile 和环境绑定，避免破坏性 schema 升级使回退失效。

## 范围与约束

- In scope（纳入）：双入口、只读扫描/源指纹、路径与冲突计划、复制或引用、新 profile 实证、旧状态升级和成组回退。
- Out of scope（不纳入）：旧 venv 原位接管、任意插件自动迁移、运行中任务复活、静默合并 profile、删除源安装和外部路径。
- 前置：M3 证据/独立复审/Git 退出门通过；RuntimeLayout、四引擎和可信历史合同冻结；样本与写入边界经批准。
- 遵循[测试证据治理](../00_预检证据/testing-and-evidence-governance.md)、[资源授权治理](../00_预检证据/risk-and-authorization-governance.md)、[Git 基线治理](../00_预检证据/git-baseline-governance.md)。
- 本轮仅规划，不扫描真实私有资料、不创建沙盒、不执行迁移或 commit/push；未来真实旧包只在已批准副本上试验。
- 导入计划改变时必须重新展示；凭据单列显式选择，脱敏日志；不依赖源 venv 可移动，也不跟随 junction 清理。

## 执行阶段

### Phase 1：建立迁移样本与只读扫描

- Purpose（目的）：识别真实来源和未知项目，保证“导入前先看清”不会修改旧安装。
- Outputs（输出）：首次/环境页导入入口、扫描结果、源指纹、识别/不支持项、外部路径和凭据分类；独立旧包副本样本表。
- Completion criteria（完成标准）：扫描无持久写入；旧包未启动也能识别资料；无法识别项保留而非当垃圾删除。
- Validation（验证）：扫描前后原包/资料/sentinel 哈希；验证中文空格、只读源、相对路径、联接与目录循环边界。
- Evidence（证据）：`<run-id>/M4/phase1/` 保存脱敏来源、扫描/API 结果、原生入口截图、前后哈希。
- Failure handling（失败处理）：权限/超时为 unknown，停止针对该项的迁移；不以修复旧环境作为扫描副作用。

### Phase 2：生成可复核映射与空间计划

- Purpose：将每个复制/引用和冲突决定变成持久合同，避免新根改变路径含义。
- Outputs：MigrationPlan，包括源指纹、目标 schema、新 profile ID、逐项源/目标、复制/引用、冲突策略、备份、验证器和切换点。
- Completion criteria：模型/数据集默认绝对引用；相对路径按旧安装语义转换并展示；容量包含新副本/备份峰值，凭据可明确不导入。
- Validation：计划序列化/错误码合同、路径白名单、跨卷/非空目标、文件名冲突、磁盘不足和计划过期测试。
- Evidence：`<run-id>/M4/phase2/` 保存计划摘要、确认前后版本、容量预算及不同冲突选择示例。
- Failure handling：源/目标/选择变化即废弃旧计划重扫；冲突未定或空间不足时不复制，不自动覆盖旧根。

### Phase 3：执行可恢复复制或引用

- Purpose：生成一致的新资料副本，同时让任意中断都不损害旧安装和当前健康绑定。
- Outputs：受管迁移操作/检查点、新 profile 待验副本、逐项完成/校验记录及源稳定性证据。
- Completion criteria：先停止源训练器或证明源稳定；复制期指纹变化触发重扫；部分副本不激活，不把旧运行中任务当进程恢复。
- Validation：文件中途变化、复制中断/取消/强杀、空间耗尽、目标锁定；重启后按现场校验而非盲用旧阶段。
- Evidence：`<run-id>/M4/phase3/` 保存操作现场、源变更/故障原始日志、复制校验和恢复结果。
- Failure handling：原安装保持；隔离未完成目标并提供继续/重扫/预览清理；不从多时刻文件拼装成可激活混合快照。

### Phase 4：实现 profile 绑定和 schema 恢复

- Purpose：使回退选择的是完整可用组合，避免仅回退代码却继续读取不兼容新资料。
- Outputs：稳定 profile ID、`release_id + profile_id + environment_instance_ids` 绑定、当前/上一健康绑定及兼容性判定。
- Completion criteria：旧 current/previous→default 是预览且备份的格式升级；破坏性迁移新建副本/快照；旧壳未知 schema 拒写。
- Validation：控制状态原字节恢复、升级每个提交点中断、旧发布读新 schema 被阻止、旧 profile/对应环境原样回退。
- Evidence：`<run-id>/M4/phase4/` 保存 schema 对照、绑定前后、备份清单/哈希、失败恢复和旧壳拒写结果。
- Failure handling：恢复精确旧状态再激活旧绑定；无法证明可恢复则保留新壳恢复模式，不让旧壳试读，也不删新旧资料。

### Phase 5：验证新 profile 并显式切换

- Purpose：通过真实用户入口检验导入资料和路径，再允许把它作为当前使用组合。
- Outputs：新 profile API/设置/预设/归档检查、原生切换流程、选择引擎重建/缓存核验和旧源保留说明。
- Completion criteria：新实例固定路径创建、通过真实验证后显式切换；旧 venv 不默认接管；回退提示迁移后新增资料不会自动合并。
- Validation：从独立旧包副本完成一次端到端导入；检查外部引用可用、源/非目标环境哈希不变；注入新 profile 验证失败。
- Evidence：`<run-id>/M4/phase5/` 保存真实 API/页面/预设值、切换与回退绑定、外部 sentinel、缓存哈希/mtime 和截图。
- Failure handling：验证不通过维持旧绑定；新副本保留诊断，不用旧 venv 补救受管环境，也不自动合并或删除资料。

### Phase 6：独立复审与阶段交付

- Purpose：证明迁移没有隐性改源，并用可追踪分支交付解锁 M5。
- Outputs：目标 M4-A1–A8 证据映射、失败链、独立复审/阶段报告、资料隐私和保留/清理说明。
- Completion criteria：全部强制样本与故障门通过，无 P0/P1；按已审核范围 commit、普通 push 并核对远端哈希。
- Validation：独立审查扫描/迁移/回退 diff 及原字节/sentinel 证据；按 Git 治理核查 `origin feat/desktop-launcher` 与本地提交一致。
- Evidence：`<run-id>/M4/phase6/` 保存 review/报告、受控样本清单、提交/push 和 `ls-remote` 输出；唯一总控记录结论。
- Failure handling：原包变化、隐私泄露或回退不精确均阻止 M5；保存现场并修复重验，不通过删除证据或降级样本绕门。

代码提交 C 与状态提交 S 必须按 Git 治理分别普通推送和核对；保存仓库外 `baseline-final.json` 后才准阶段 done。任一回执缺失维持 in progress/blocked。
