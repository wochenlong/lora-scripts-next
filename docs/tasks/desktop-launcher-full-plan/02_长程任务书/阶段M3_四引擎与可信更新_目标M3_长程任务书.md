## 目标

让 AI Toolkit、DiffSynth 达到与 Kohya、Anima Fast 一致的安装控制、独立检查/诊断、RepairPlan、精准修复和路径/运行时隔离合同，以四引擎轻量冒烟验证控制分支；让更新发现和历史识别建立在可离线重验的信任证据上。

## 范围与约束

- In scope（纳入）：新增两引擎、首批回归、锁定配方/资产、签名 catalog、历史 receipt、轮换/撤销及用户显式激活。
- Out of scope（不纳入）：其他未适配引擎、旧 venv 接管、壳替换、生产密钥代管和 M6 最终复验。
- 前置：M2 证据/独立复审/Git 退出门均通过；本计划通过审核且 M0 冻结了本阶段资源和假设。
- 遵循[测试证据治理](../00_预检证据/testing-and-evidence-governance.md)、[资源授权治理](../00_预检证据/risk-and-authorization-governance.md)、[Git 基线治理](../00_预检证据/git-baseline-governance.md)。
- 本轮仅编写任务书，不运行产品、不安装、不下载、不训练、不 commit/push；下列步骤均为未来已授权执行时的指令。
- 首批运行目录/standalone 所有权和跨进程锁继续适用；依赖定点修复必须复用快照、generation、dirty 和引用闭包恢复。

## 执行阶段

### Phase 1：冻结新增引擎合同与配方

- Purpose（目的）：保证新增两引擎使用相同受管规则，避免 GUI Python、上游或补丁漂移。
- Outputs（输出）：两引擎 EngineCapabilities、兼容合同、Python ABI、固定上游/补丁、依赖锁、工具/资产哈希及来源表。
- 候选源码门：从已推送 feature 完整 commit 生成训练器源码及已编译前端归档，必须包含本计划 worker/引擎/路径实现；固定哈希/recipe并在测试catalog标明候选身份，不冒充经验证main。
- Completion criteria（完成标准）：所有必要资产可获取且有预算；适配器读取发布配方，未知/不支持动作明确拒绝。
- Validation（验证）：解析实际发布清单；核对现有 `mikazuki/engines` 对应 manifest/environment/installer；合同测试覆盖差异。
- Evidence（证据）：`<run-id>/M3/phase1/` 保存配方摘要、资产清单、能力对照和源码身份。
- Failure handling（失败处理）：缺锁/资产时标待适配，停止对应安装；不套 GUI 3.10、不向历史源码注入临时补丁。

### Phase 2：接入只读探测与精准修复

- Purpose：让每项故障有最小可解释动作，且检查、执行探测和变更边界一致。
- Outputs：AI Toolkit/DiffSynth 的 inspect_readonly、probe_execute、repair_apply；UI 独立状态与修复计划入口。
- Completion criteria：状态丢失可按独立探测补登记；单包/源码/基础 Python 修复不整包重装；用小夹具冒烟核对GUI与非目标引擎不变，不在真实引擎环境验收。
- Validation：只用合成/小夹具选择必要修复成功分支，覆盖改包未提交、dirty/generation、lease、路径隔离、失败拒写及少量恢复分支；复用同路径快照和共享基础Python引用闭包合同，不破坏真实引擎环境做验收。
- Evidence：`<run-id>/M3/phase2/` 保存计划/变更记录、非目标哈希、进程/锁现场、恢复重验结果。
- Failure handling：恢复失败维持 dirty，提供继续修复/健康绑定回退/显式重建；不得因进程退出就标健康。

### Phase 3：完成四引擎独立入口与修复冒烟

- Purpose：分别核对四引擎检查、诊断、计划和修复控制入口，并发现新增适配对首批的影响。
- Outputs：四引擎独立配方/解释器/依赖/上游/补丁身份、合成状态、RepairPlan与必要冒烟结果。
- Completion criteria：AI Toolkit/DiffSynth 与Kohya/Anima Fast 各自入口可调用；各有小夹具必要成功分支，关键拒绝/恢复分支和互不干扰证据齐备；真实验证跳过项不作pass。
- 来源身份：交付实现与receipt锁定候选源码一致；禁止原固定main/dev加开发repo overlay、PYTHONPATH或源码联接补丁冒充最终可安装发布。本阶段不要求真实引擎安装实测。
- Validation：四引擎分别以合成/小夹具核对状态→RepairPlan→修复，覆盖路径隔离、dirty/generation、lease、失败拒写和少量必要恢复；真实安装/导入、破坏后修复/再训练、GPU小张量、完整模型加载/最小反向、短训练及权重读取核验均 `skip + CR-004`。
- Evidence：沿用 `<run-id>/M3/phase3/<engine-id>/` 保存冒烟原始输出、状态/非目标摘要与跳过说明，不新建报告。
- Failure handling：控制合同失败仍保留现场并回到对应适配步骤；GPU/模型缺失不阻塞本阶段，也不填真实验证pass。

### Phase 4：实现并验证清单信任协议

- Purpose：使远端候选身份、配方动作和发布来源可验证，不把镜像当信任根。
- Outputs：版本化 catalog、确定性 payload、签名封套、信任根、序号/时间策略、最低壳版本、平台/资料兼容检查和轮换证明。
- 同包前置：交付二进制提供显式、可审、只读配置的沙盒测试会话；后端只接受固定fixture ID，验证新隔离根/固定端点/公钥/动作白名单，禁止UI传任意URL/密钥/命令或修改生产信任。
- Completion criteria：篡改、错误签名/平台、过期、新增信任重放、未知 schema 均拒绝；轮换须旧可信密钥授权，动作只选内置 ID。
- Validation：按影响选少量必要正反向量、可控签名端点与真实资产，复用有效时钟/轮换证据；同SHA普通根拒测试资产、显式沙盒会话核对必要链路并证明生产状态不变，不重复全矩阵。
- 身份门：另SHA测试构建仅补协议证据，不抵M6最终包A4/A8；无同包可审通路且无维护者生产资源时对应格blocked，不能称全部完成。
- Evidence：`<run-id>/M3/phase4/` 保存公开测试向量/公钥、响应原文与验证结果；不保存私钥或认证凭据。
- Failure handling：候选校验失败不改本地状态；生产签名条件不足保持内置清单/手动模式，记录未上线边界，不开放无签名远端执行。

### Phase 5：持久可信历史与非阻塞更新

- Purpose：防止最新远端列表或公钥替换破坏本地离线启动与回退。
- Outputs：receipt 保留原始封套/payload/摘要、信任链、接受序号与时间依据；内置来源记录所属壳构建和嵌入清单摘要。
- Completion criteria：schema 1 可读、未知格式拒写；下架/过期与已验证安全撤销分开；保留历史公钥证明，可信撤销阻止自动及显式安装/激活/回退。
- Validation：选取可信离线回退成功、已知撤销拒绝与准备失败不改current等关键分支，必要时补历史兼容恢复；下架/过期/重放等未受影响证据可复用，保留各功能规则而不重复全套矩阵。
- Evidence：`<run-id>/M3/phase5/` 保存历史 receipt 重验、清单来源/日期/刷新 UI、缓存哈希/mtime 和绑定前后对照。
- Failure handling：无法证明信任的历史标 unknown 并保留实体；拒绝新变更，不凭本地 verified=true 自授信任或因网络失败推断撤销。

### Phase 6：阶段审计、提交与远端核对

- Purpose：把功能、真实证据和分支状态封成可复核的 M3 交付，再解锁 M4。
- Outputs：测试矩阵、限制/not-run、失败修复链、独立复审报告、M3 完成报告及 Git 对账。
- Completion criteria：目标 M3-A1–A7 按v0.5范围有证据；四引擎必要冒烟及信任关键分支通过，CR-004跳过项明确；无 P0/P1；按已审核范围 commit 和普通 push，远端哈希一致。
- Validation：审查者独立重读 diff/证据；依 Git 治理用 `git -c http.proxy=http://127.0.0.1:11809 -c https.proxy=http://127.0.0.1:11809 ls-remote origin refs/heads/feat/desktop-launcher` 核对提交。
- Evidence：`<run-id>/M3/phase6/` 保存报告、review、提交/推送结果及时间；更新唯一总控，不建立第二进度文件。
- Failure handling：复审/P1、push 或远端不一致均不解锁 M4；保留本地提交，不 force push、不混入他人改动，按治理处理。

代码提交 C 与状态提交 S 必须按 Git 治理分别普通推送和核对；保存仓库外 `baseline-final.json` 后才准阶段 done。任一回执缺失维持 in progress/blocked。
