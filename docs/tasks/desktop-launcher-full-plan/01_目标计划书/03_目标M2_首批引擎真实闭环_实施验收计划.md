## 目标与回答的问题

实现 Kohya、Anima Fast 的独立安装控制、检查、诊断、RepairPlan、精准修复与隔离，回答“训练器或某个引擎坏了，桌面端能否独立处理目标且不影响另一引擎”。本阶段仅以轻量冒烟验证控制合同，不据此声称真实引擎环境或训练可用。

## 范围与前置条件

- 包含 RuntimeLayout、独立控制 worker、网页/桌面共用配方/动作/锁、两引擎锁定配方与分层状态表达；真实四层验证按 CR-004 跳过。
- 其他引擎保留待适配状态；AI Toolkit/DiffSynth 的正式闭环归 M3，不将普通 Anima 与 Anima Fast 混同。
- 开工需用户后续审核范围且 M1 完成门通过；仅落实小夹具和必要工具的来源、路径及预算，不以 GPU、模型或约16GiB显存实测为本阶段前置；引用[资源授权](../00_预检证据/risk-and-authorization-governance.md)和[Git 治理](../00_预检证据/git-baseline-governance.md)。

## 验收标准

1. 先做 RuntimeLayout 探针：七类根、允许物理根、受管 junction 和 `.python` 稳定归属有合同；重建 run 不丢引擎，非法外指仍被拒。
2. 已知 `_resolve_child` 与 extensions 联接冲突得到有边界的适配，禁止通过移除路径安全检查绕过；旧 CLI 和不支持新合同的历史发布行为清楚。
3. worker 使用经校验的基础 Python，启动不依赖 GUI、Torch 或整套 app import；基础 Python 坏由 Rust 先恢复。
4. 抽取纯配方、探测/计划/执行核心，网页和桌面共用动作及跨进程锁；`inspect_readonly`、`probe_execute`、`repair_apply` 分离，检查不隐式修复。
5. Kohya 受管模式仅 standalone，阻止 main_env fallback 修改 GUI；非受管兼容入口保持可识别的旧行为。
6. Kohya 当前 3.10、Anima Fast 当前 3.13 各自冻结精确 patch/ABI、上游/补丁和依赖资产；不套用 GUI Python 3.10.19。
7. 两引擎检查/修复入口可调用；用合成/小夹具核对独立状态、RepairPlan、一个必要成功分支及关键拒绝/恢复分支。真实安装/导入、GPU、模型、短训练和权重核验均为 `skip + CR-004`。
8. 用隔离夹具验证 GUI 控制通道与引擎互不依赖；目标修复前后非目标路径、资料及旧健康绑定 hash 不变，dirty/generation、lease、失败拒写有效。
9. 候选中的worker/引擎控制实现与归档、前端、recipe/catalog和receipt身份可对账。原始main/dev加开发仓库overlay不能作为交付身份，测试候选不默认冒充main稳定版；本项不要求真实引擎安装实测。
