## 目标、范围与依赖

回答：旧安装资料能否经预览导入新 profile，在源变化、冲突、中断或 schema 升级失败时仍保留可用旧安装和正确回退绑定？
纳入：首次/环境页双入口、只读扫描、指纹/冲突、复制或引用、凭据单列、新 profile 试运行与显式切换、资料版本兼容恢复。
不纳入：旧 venv 原位接管、迁移运行中进程、自动合并两 profile 新增资料、删除源安装或外部模型/数据集。
前置：M3 完成门通过，RuntimeLayout/引擎/版本信任合同稳定；受管夹具和真实旧包样本的范围/备份按[授权治理](../00_预检证据/risk-and-authorization-governance.md)批准。
M4 后解锁 M5；M6 再对最终同一制品执行完整新安装与迁移回退复验。

## 验收标准

| 编号 | 可验收结果 | 失败条件 |
| --- | --- | --- |
| M4-A1 | 扫描只读，显示源指纹、目标 schema、路径映射、冲突决策、空间和验证器 | 扫描就修源、隐式覆盖或选择非空旧根当新根 |
| M4-A2 | 默认新 profile；设置/预设/归档/输出可复制，模型/数据集默认绝对引用 | 相对路径含义改变、外部目录被移动/递归删除 |
| M4-A3 | 复制前停源或证明稳定，源变化触发重扫；中断保持新副本未激活 | 混合快照激活、源仍运行却声称一致 |
| M4-A4 | profile 稳定 ID；绑定为 release_id + profile_id + environment_instance_ids，保存上一健康绑定 | 回退只切 release、旧版本直接读新破坏性 schema |
| M4-A5 | default 旧 registry 升级有预览、原字节备份和兼容检查；未知格式拒写 | 假设任意旧壳都能读新格式、不可恢复格式写入 |
| M4-A6 | 新 profile 经 API/真实用户入口验证后显式切换；失败恢复旧 profile/对应环境 | 仅目录存在或 JSON 成功即通过、旧源被污染 |
| M4-A7 | 旧 venv 默认不接管，选择引擎按新合同重建；缓存复用须验哈希 | 直接复制/重定位旧 venv、默许继承未知包漂移 |
| M4-A8 | 凭据显式选取且普通诊断不含秘密；清理有单独预览且不跟随 junction | 日志泄露、回退静默合并或删除新旧资料 |
