# 阶段 4：隔离重建与从零真实验收

## Purpose

在全新工作目录和全新依赖环境中重建交付物，验证最终用户路径不依赖开发机残留状态，并完成完整测试、真实模型和人工验收。

## 开工前硬门槛

- Phase 0–3 完成门全部通过，canonical task book、manifest、设计书和验收矩阵已更新；
- 代码已形成可审计的候选 commit 或干净源码包；
- 已准备脱敏样本、远程运行时凭据注入方式、本地模型资产清单和资源上限；
- 已确认隔离目录不包含旧 .venv、node_modules、缓存、配置、SQLite、模型和测试输出。

## 执行步骤

1. 创建新的隔离 worktree/源码目录，记录源 commit、操作系统、Node、Python、包管理器和 Git 状态。
2. 建立全新 Python 虚拟环境和前端依赖目录，按锁定文件安装依赖。
3. 执行前端检查/构建、后端导入/启动和健康检查；记录完整命令与输出。
4. 使用空配置运行 Zero-Short，确认 UI 可启动、不会外发或自动下载，且给出可操作提示。
5. 注入不落盘的远程 profile，完成 Tag、natural、combined 真实低限额样本；确认 remote-first。
6. 让远程路径受控失败，在用户显式启用本地后验证 Qwen3-VL-2B 兜底、取消、恢复和资源上限。
7. 验证预览不写盘、批量取消保留已完成项、失败重试只处理失败项、外部修改触发 conflict、Dataset Editor 不破坏 mixed caption。
8. 运行完整测试矩阵：unit、contract、integration、gray、frontend、real、EDD、Zero-Short；保存 commit、环境、样本 hash、profile/prompt revision。
9. 执行隐私扫描和 Git 状态扫描，确认没有 Key、本地路径、用户图片、原始响应、模型二进制和缓存进入产物。
10. 清理隔离目录中的临时图片、模型、runtime、Key、缓存和原始响应，保留摘要、hash、日志和清理报告。
11. 由人工验收人按验收表复核桌面、窄屏、键盘、空配置、错误、取消、重试、隐私提示和旧 Tag 回归。
12. 更新 canonical task book、manifest、最终复盘和 O5 证据，只有全部门禁通过才允许标记完成。

## 完成标准

- 新环境可按同一命令清单重复建立；
- 前后端构建、完整测试、真实远程优先/本地兜底和人工验收全部有证据；
- Tag/natural/combined、写回、取消、重试、冲突保护和编辑器安全均通过；
- 清理完成且 Git、日志和报告无秘密与用户数据；
- 无未授权 P0/P1，最终复盘明确写出隔离重建通过。

## Failure handling

- 依赖或启动失败：生成 Phase 4 failure report，保留最小错误日志，修复后从隔离目录重新开始，不直接复用半成品环境。
- 远程不可用：记录网络/服务失败；只有已定义且用户显式启用本地 profile 时才继续 fallback 验证，否则阻止完成门。
- 任一真实样本或人工验收失败：保留失败摘要和输入 hash，回到对应阶段修复，重新建立隔离环境后再验收。
- 发现秘密或用户数据泄露：立即停止发布，清理凭据和证据，按风险治理升级为 P0/P1。
