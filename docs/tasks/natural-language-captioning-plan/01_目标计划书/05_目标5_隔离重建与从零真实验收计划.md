# 目标 5：隔离重建与从零真实验收

## 目标

在不复用开发工作树、旧依赖环境、旧配置、旧模型缓存和旧测试产物的前提下，从干净来源重新建立运行环境，证明自然语言打标功能的后端、前端、Dataset Editor、共享 LLM 管理和真实模型路径可被用户完整复现。

## 必要前提

- O1–O4 完成门全部通过，canonical task book、manifest、设计书和验收矩阵已经冻结；
- 生成一个全新的 worktree 或干净源码包，并记录源 commit；
- 使用新的 Python 虚拟环境和全新的前端依赖目录；
- 远程真实测试仅使用公开或已脱敏样本，API Key 通过运行时安全注入，不写文件；
- 本地视觉模型只从登记的 asset manifest 获取，记录 revision、SHA、资源上限和清理策略。

## 完成条件

- 依赖安装、后端启动、前端构建和健康检查全部从零通过；
- 完整测试矩阵通过：unit、contract、integration、gray、frontend、real、EDD、Zero-Short；
- Tag、natural、combined 三种模式各完成一条真实链路；
- 远程 profile 可用时始终优先；远程失败且本地明确启用时才切换 Qwen3-VL-2B；
- 预览不写盘，批量任务支持进度、取消、失败重试、文件冲突保护和原子写回；
- Dataset Editor 不会用 Tag 清理规则破坏 natural/mixed caption；
- 完成前后 hash、失败报告、隐私扫描、资源清理和人工验收记录；
- 从隔离环境产生的证据中没有 API Key、本地路径、用户图片、原始响应或模型二进制；
- 未授权 P0/P1 为零。

## 测试与证据

- 重建脚本或逐步命令清单、源 commit、OS/Node/Python/依赖版本；
- 前后端安装、构建、健康检查和完整测试日志；
- 远程优先成功、远程失败转本地、两者不可用、取消和恢复的报告；
- 3–5 张脱敏样本的 Tag/natural/combined 结果摘要与输入 hash；
- 写回前后 hash、conflict guard、cache revision 和清理报告；
- 人工验收表：桌面、窄屏、键盘、空配置、错误提示、隐私提示和旧 Tag 回归。

## 完成门

只有以下条件全部满足，O5 才能标记 complete：

1. 新 worktree/新环境的复现过程可由另一位执行者按文档重复；
2. 所有必测命令和真实样本结果均有可审计证据；
3. 隔离环境删除后，不能依赖其残留状态解释主路径成功；
4. 计划文档、代码、测试证据和用户验收记录一致；
5. 最终复盘明确写出“隔离重建通过”。
