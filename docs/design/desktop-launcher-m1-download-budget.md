## 计量单位与用户设置

计量单位为 `http_body_delivered_v1`：有界正文 reader 交付给下载器的 HTTP 正文，加上无法确认是否完成的持久预留所产生的保守扣账。每次读取最多预留 64 KiB，先持久化预留，再读取、再结算。HTTP 库的预读、TLS、TCP、DNS、握手及任意子进程流量不在这个单位内，不能将它称为网卡流量硬限制。

按 2026-10-30 用户要求立即修改的 CR-007，新工作区默认允许下载，无需先设置额度。每个安装根独立保存下载计量；首次需要远程下载时自动建立不限累计用量的账本。全部命中已验证缓存时不必建立账本或 receipt。开发验收的网络资源预算属于外部测试台账，不作为普通用户安装前的配置步骤。

环境页默认收起“高级：下载用量与限制”。累计上限默认关闭；用户可主动开启并设置非零整数，支持字节、MiB 和 GiB。关闭上限保存为 `root_cap_body_bytes: null`，保留已有用量、历史 receipt 与策略代次；已有数字上限原样读取，后续默认下载不会覆盖它，用户可显式关闭。首次读取设置保持只读，不为展示界面创建工作区。

累计消耗为已交付正文与保守扣账之和。正在读取的预留另外占用余额。失败、取消、资产摘要错误、缓存隔离和用户再次尝试均不退还已经扣除的用量。请求次数、重试次数、跳转次数和操作总时限与正文额度同时约束，避免空正文请求无限重试。

## 持久状态与恢复

根内固定文件为 `state/download-budget-enrollment.json`、`state/download-budget.json` 和 `state/download-receipts/<operation_id>.json`。启用采用 Pending 标记、genesis 账本、Active 标记三步；只有精确一致的 genesis 才能恢复未完成启用。Active 标记存在而账本丢失、身份不符、未知 schema、坏记录或历史 receipt 与身份丢失的组合都会拒绝接管，不能重建零账。

已有根启用前的制品历史标为 `not_measured`；没有发现制品证据也不代表过去网卡流量为零。本地有写权限的用户若删除全部历史或恶意重写全部状态，不属于此账本能够抵御的攻击边界。

预算写入必须处于同一真实工作区租约内。一个产品操作复用一个预算 session；安装的源码、uv、Python 和全部 wheel 共享它。下载任务取消或到达总时限时先 abort 并 await 网络任务，再结算和释放租约。强杀后只有重新取得租约、确认当前进程没有活动 session，才可以认领遗留预留并形成 Interrupted receipt。

环境页的“结清中断预留”执行上述独立恢复，不发起下载，不修改上限，也不重置计数。保存上限或关闭上限均使用 expected revision；过期草稿拒绝保存，轮询不会覆盖用户已编辑的输入。未知状态或仍有未结下载时，修改设置会拒绝。

命令行与原生界面复用同一核心实现：`--manage download-budget <absolute-root>` 只读查询；`--manage set-download-budget <absolute-root> <cap_bytes|off> new` 在尚无账本时保存设置；已有账本时将 `new` 替换为明确的 expected revision。`off` 关闭累计上限。`--manage reconcile-download-budget <absolute-root>` 显式结清。修改命令不会从“已存在”错误自动切换成覆盖保存。

终态先写进账本的 terminal outbox，再幂等投递独立 receipt，最后清 outbox。任一失败均保留可恢复状态；相同 receipt 不重复计账，不同内容拒绝覆盖。receipt 包含开始与结束累计快照、冻结操作限制、观察与保守扣账、请求及缓存计数和结果。预算结果与实际安装／修复结果是分别可核对的事实；有非零消耗的操作仍可能失败。

## 下载入口

正式远程制品统一走 `ArtifactDownloads` → `controlled_download::download_with_budget`。完整安装显式共享同一 scope；源码修复和基础 Python 修复只下载一个固定资产；预取与历史源码／uv 归档也使用同一预算实现。有效缓存先核精确长度、摘要和 partial sidecar 合同，未知 sidecar 不能被缓存命中绕过。

下载 client 禁止自动跳转。每跳、416 后一次重试均建立独立 attempt，并共享冻结网络策略与累计限制；HTTPS 降级、内嵌 URL 凭据、错误范围和不匹配验证器会拒绝。错误及跳转正文最多消费 4 KiB 诊断且照常计账，不保存原正文。达到应用正文额度以后停止交付，不能借错误处理无限读取。

累计上限关闭时，仍按受信任配方限制单个资产、单次操作、请求次数、重试和截止时间，并核对长度与摘要。用户开启累计上限后，读满资产仍需有额度预留 EOF／溢出探测；若额度恰等于此前消耗与最后资产正文长度之和，reader 会保守停止并保留完整 partial，不能在零余额下额外读取。用户可增加或关闭累计上限后重试。

正式固定配方的 uv 始终离线。历史未锁 requirements 配方的 uv 同样强制离线，避免子进程隐式下载绕过制品计账；它只能复用已有本地缓存，缺缓存时提示选择已适配的固定配方版本。历史版本完整在线安装仍需后续版本适配阶段提供固定配方，不能把这条离线路径报告为已完成历史在线安装验收。训练器运行时请求与健康探测也不属于制品预算。
