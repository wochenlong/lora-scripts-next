## 4. 词库下载生命周期

### 4.1 何时下载

- 项目启动只检查本地状态，不联网安装。
- 用户第一次开启中文释义时，如词库未安装，通知设置页并创建一次后台下载任务；翻译查询本身立即可返回现有缓存/已启用兜底。
- 已安装词库不会每次更新；检查更新和下载安装均有显式入口。
- 默认仅词库时，没有词库先显示等待状态；下载安装成功后自动补查当前任务未命中项。
- 已允许网络/LLM时可以先兜底；新词库就绪后重新按词库优先投影，原 caption 不变。
- 下载任务在关闭弹窗、切图、离开数据集页面时继续；取消下载需点击对应任务“取消”。

### 4.2 下载服务与日志

复用现有 `ChineseDictionaryService` 的 SHA/SQLite 校验和原子替换；参考 Tagger `model_fetch.py` / `progress.py` 的下载进度与日志桥接，优先迁移可复用代码。统一下载任务只管理本功能资源。

任务状态：`queued → checking → downloading → verifying → installing → completed`，另有 `failed/cancelled`。同一资源和版本只允许一个任务；再次点击返回已有任务。

记录 task ID、资源类型/名称、版本、来源、已下载字节、总字节、错误码、重试次数、时间。总字节未知时显示已下载量，不制造百分比。进度通过 status 轮询给 UI。

终端与文件日志必须输出：开始、来源、进度、校验、成功、失败、取消、重试。进度最多每两秒一条且数据变化时才输出；不记录 API Key 或完整 caption。统一以 task ID 关联。

网络临时错误默认最多自动重试两次，退避 1s、2s；认证、不可用版本、校验失败不盲目自动重试。失败保留原因与重试按钮。取消清理临时文件，已安装文件不删除。重启后将运行中的下载标为 interrupted，可显式重试；旧词库继续可用。

当前词库路径保持 `assets/tag_translation/danbooru/tag.sqlite`，明确是后端机器路径。更新只替换通过校验的新库；查询与原子替换使用锁协调。不把旧词库更新失败解释成已安装词库不可用。

### 4.3 查询性能和最长匹配

精确查原始 tag 优先，其次下划线/空格规范化，最后最长短语匹配。禁止子串匹配将人名、未知组合或半个词误译。

在独立派生索引中登记规范化词条，不修改第三方数据库结构。派生索引以词库 SHA 和 normalization revision 版本化。多词短语先尝试整条匹配，再按词边界从最长到最短拆分；仅完整覆盖的可靠组合可标为 dictionary 命中，存在未知片段时将整个原 tag 交给兜底，保留原 tag。

## 5. 本地小模型安装与服务管理

### 5.1 建议运行路线

建议首版用受项目管理的 `llama.cpp` server 加 Qwen3.5-0.8B GGUF，只处理标签文本。采用官方运行时发布包，避免给训练 Python 环境安装另一套 torch/transformers。CPU 为最低可用路径，GPU 后端必须通过环境探针后显示支持。

来源证据（2026-10-01）：[Qwen 模型卡](https://huggingface.co/Qwen/Qwen3.5-0.8B)、[ggml-org GGUF 仓库](https://huggingface.co/ggml-org/Qwen3.5-0.8B-GGUF)、[llama.cpp 项目](https://github.com/ggml-org/llama.cpp)。模型存在与兼容服务方式可核实；中文标签质量、具体量化版本和本机资源占用尚未实测。

实施前固定运行时 release、模型仓库 commit、量化文件、大小与哈希；先通过 Windows CPU 的加载、JSON 翻译和停服探针，再登记到可安装清单。首版只展示验证过的组合，不动态默认使用 latest，不静默换成其他模型。

### 5.2 三种 LLM 来源

| 来源 | 页面表单 | 用户操作 |
| --- | --- | --- |
| 项目管理的本地小模型 | 模型、量化、运行设备、安装位置、状态 | 安装运行时及模型、启动、停止、测试翻译、打开日志 |
| 已有本地服务 | endpoint、model、可选 Key | 检查连接、保存；不管理其安装和进程 |
| 远程 API | HTTPS endpoint、model、Key | 检查连接、保存、替换/清除 Key |

本地安装卡显示“运行在后端机器”。安装下载详情统一出现在“词库与下载”，LLM 卡同步显示同一个任务进度和跳转按钮。

模型下载到 `assets/tag_translation/models/<model-id>/<revision>/`；运行时到 `assets/tag_translation/runtime/<platform>/<release>/`；任务和运行状态另存。不提交模型或运行时二进制。

受管服务默认仅监听后端回环地址，使用选定空闲端口；固定参数调用子进程，Windows 隐藏窗口。启动前检查资源存在、版本支持和内存信息；健康检查通过才显示 ready。端口占用、加载失败、进程退出可见并可重试。停止只终止本项目启动并登记的进程，不结束用户自己的服务。

默认不随项目自动启动模型。用户点击启动后可选择“下次自动启动”，应用退出清理受管进程。卸载前停止受管模型，模型文件和运行时分别提供删除选项，译文缓存独立保留。

### 5.3 翻译配置

默认本地 batch size 8、并发 1、每次推理 timeout 60s，作为待探针验证的起始值；远程保留可配置 batch/concurrency/timeout/retries。关闭思考模式、使用 JSON 约束；参数由运行时能力决定，不把特定厂商参数强塞给所有服务。

连接测试发送少量固定标签并验证真实翻译 JSON，不仅检查 `/models` 或“OK”。结果区显示耗时、成功项、错误码和模型名；既有本地服务和远程测试不替换保存配置。

## 6. 自动回退与缓存优先级

逻辑来源顺序固定为 `Danbooru → MyMemory → 当前 LLM → 无译文`。词库不可用视为该层不可用，不阻断后续已允许来源。

每个标签的执行顺序：

1. 查询当前词库及匹配索引。
2. 按当前模式读取可用成功缓存：MyMemory 缓存优先于当前 LLM profile 缓存。
3. 无有效成功缓存时才请求网络。
4. 网络未命中或失败时请求已配置、已就绪且被允许的 LLM。
5. 仍无结果则记录 missing/error/not_configured，英文保持可见。

因此来源优先级与外部调用优先级分开：已有有效 LLM 译文时不为了优先级再购买一次网络请求；刷新或切图只读本地。显式“重试失败项”跳过失败冷却；显式“重新翻译”才重新请求成功项。

新增/删除/重排 caption tag 后更新全数据集唯一集合，只为新增项补查本地；外部补翻译由开关开启、显式来源切换或设置页重试触发。全数据集任务不受当前筛选、分页或单图选中限制。

## 7. 缓存契约与迁移

- 存储语言统一为规范化键，例如 `zh`；页面语言保留 `zh-CN`。API/manager/store 全部调用同一个 locale helper。
- 成功译文继续使用 SQLite v2 表，以 tag key、locale、provider、profile revision、normalization revision 隔离。
- LLM profile 包括接入类型、endpoint、model、提示词 revision、推理参数和显式配置修订号。替换/清除凭据更新修订号，不把 Key 作为响应字段或日志输出。
- 后端返回 dictionary revision、LLM profile revision、cache epoch。前端取得有效 revision 后才复用相应缓存，切换配置后不得先闪现旧模型译文。
- 浏览器只保存偏好、当前数据集 session 和有限内存加速索引；后端成功缓存为权威。旧浏览器译文因无 revision 不能直接当作新 profile 结果，可保留隔离区，后端本地核对后恢复。
- 缓存合并使用 update，不以新 LLM 返回映射替换已命中的结果；missing/error 永远不覆盖有效成功项。
- 旧 `zh-CN`/`zh` 行事务迁移为统一键，同 provider/profile 冲突保留更新时间较新的合格译文；两次迁移幂等，旧表/备份留存便于回退。
- 成功缓存清理仅删除所选 provider；词库不删除。失败记录清理是独立动作，详情写清影响范围。
- 共享请求键包含 locale/provider/profile/tag；同键去重，换模型不复用旧 in-flight。取消 UI 订阅不清成功缓存；显式清缓存提升 epoch，旧任务不得把已清缓存重新写回。

## 8. 失败状态、重试与进度

### 8.1 逐项状态

响应每项包括 `tag、translation、source、status、cached、error_code、retryable`。status 为 `translated/missing/error/not_configured/cancelled`；临时沿用 hit 的客户端必须有适配层。

| 情况 | 建议错误码 | 行为 |
| --- | --- | --- |
| 词库下载/校验失败 | dictionary_download_failed / dictionary_invalid | 旧库继续用，无旧库则进入允许兜底 |
| 网络超时/限流/额度耗尽 | network_timeout / rate_limited / quota_exhausted | 保留原因；自动模式继续 LLM |
| Key 无效/LLM未配置 | llm_auth_failed / llm_not_configured | 不自动重试认证；打开设置修正 |
| 模型未启动/进程退出 | local_model_not_ready / local_model_exited | 显示启动/重启入口 |
| JSON缺项/非法翻译 | llm_invalid_response / llm_invalid_translation | 小批次重试缺项，已成功项保留 |
| 所有来源无可用释义 | no_translation | 保留英文；可手动再次尝试 |

MyMemory 默认并发 2、一次请求最多重试两次；遇额度耗尽/限流停止该 provider 剩余批次，避免大量重复请求，自动模式继续 LLM。LLM 默认最多重试两次；截断时拆批；取消任务停止后续批次。

失败冷却默认 60s，429 优先服务 Retry-After。认证/未配置状态等待配置修订再尝试，手动重试总是可用。永久失败黑名单不再参与成功缓存查询。历史失败表不继续永久屏蔽标签；升级后转为历史诊断记录。

### 8.2 简单 N/N 与真正的增量进度

由后端翻译 job 统计，而非等待前端 500 条返回。LLM 利用现有 `resolve_stream`/batch 完结事件；词库、网络每个标签确定最终结果时更新。前端轮询 job 状态，主界面仅显示“正在查询释义… N/N”。

`N = 成功 + 未命中 + 最终失败`，缓存命中与词库命中计入成功。一个 tag 先网络失败再交给 LLM 时还不算完成；最终结果只能计数一次。分母为去重后的全数据集标签数，在创建任务时固定。

失败重试生成子任务，分母只计算失败项；成功任务最后 N/N 不等于全部翻译成功，主界面另显示“未翻译 3 个”，详情放在“缓存与任务”。取消保持真实 N/N，不强制补满。任务结束后能立即取逐项结果。

任务状态：queued/running/completed/partial/failed/cancelled/interrupted。关闭弹窗、切图不取消任务；进程重启标 interrupted，用户可继续处理未完成项，成功缓存保留。

现有 resolve/兼容 dataset-editor 入口保留；本地查询使用 local_only，不下载、不外发。每次上传最多 500 tag、每个 tag 200 字符、总字符 100,000；任务级标签上限默认 50,000，超限明确报错，不静默丢弃。创建任务只发送 tag，不发送图片、路径和 caption。

拟新增后端 download_jobs、local_model_service、translation_jobs 三个薄模块；复用现成下载器和 llama.cpp，不从零写推理引擎。前端设置弹窗拆页签子组件，API client/composable 管理轮询，页面不复制进程或下载逻辑。
