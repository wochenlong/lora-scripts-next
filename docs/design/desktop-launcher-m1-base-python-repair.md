# M1 基础 Python 组件与引用环境修复合同

基础 Python 位于安装根的 `python/3.10.19`，多个受管环境可以同时引用它。此操作恢复完整的固定组件，清单包含 4184 个原始文件；用户依赖包、虚拟环境的绝对路径、训练器源码和用户资料均受保护。单包损坏继续使用单包修复入口。

环境页提供独立的组件检查、文件清单、全部引用与阻断原因。预览以 Rust 读取文件，基础 Python 缺失或损坏时仍能使用，不先运行被检查的解释器。执行接受预览摘要，取得工作区租约后重新核对；预览之后的引用或内容变化会使原计划失效。

引用发现覆盖 `e/<实例>`、`environments/<发布>/instances/<实例>/gui`、实例记录与登记绑定，并读取受限的 `pyvenv.cfg` 核对基础路径。未绑定的干净实例、本来 dirty 的初始孤儿也必须被发现。旧环境缺少可验证归属、未知记录、包修复尚未结束或不受支持的引用会阻止替换。不会搜索或接管外部个人环境。后续引擎安装表须在 M2 接入同一引用合同。

执行先用可信 uv 和固定归档在独立位置准备候选，对候选运行完整的 Rust 文件验证。原组件中的可疑代码不参与候选构造。随后持久化修复意图、停用整个引用闭包、独立复制原组件观察字节，再在原绝对路径发布可信组件。原来已经损坏的快照用于保留现场，不能作为恢复健康的证据。

登记格式 3 的基础组件 gate 与实例格式 3 的专用 pending 分别表示全局停用和逐实例复验。旧格式 1/2 仍按其原合同读取；升级前保存原始字节。尚未写入登记 gate 的 Prepared 意图也阻止普通安装、修复、切换、删除和启动。普通入口同时检查登记与意图，避免多文件提交期间启动半完成的环境。

发布后逐个核对环境原文件、固定源码与工具，并运行解释器归属、完整依赖和关键导入验证。本来干净的引用全部通过后才提交新代次；初始 dirty 孤儿仍保持 dirty。所有状态提交完成后一次解除全局停用。原健康标记清除，下一次真实服务健康检查通过后才能重新记录健康。

意图只接受固定根、固定组件、已知阶段及精确的候选、快照和发布路径。强杀后的恢复按已记录的 old/new/missing 状态推进；第三种未知内容保留并拒绝覆盖。Python minor junction 只接受精确目标；读取重解析数据时不跟随目标，因此能识别目录交换期间暂时悬空的合法别名。

候选记录先写独立临时文件、同步并读回，再以不覆盖现有文件的原子操作发布。登记、实例与意图的未发布临时文件统一放在本事务的 `backups/<事务>/atomic-writes`，强杀残留保留在该受管命名空间。其他状态目录中的未知临时文件仍参与保护核验，不能通过泛删或忽略扩展名解除阻断。

取消与失败保留能够解释现场的意图和独立快照；不能仅因进程退出、恢复了旧字节或组件本身完整就清除 dirty。未知格式、快照损坏、引用验证失败或非目标内容变化时维持停用并报告原因。

验证分为状态机与小目录检查、真实组件恢复、跨进程强杀恢复和多引用验证。单个环境的原生结果不替代双命名空间、多引用或引擎验证。每项实际状态与证据仅在[总控目标索引](../tasks/desktop-launcher-full-plan/00_总控目标索引.md)登记；本合同不表示 M1 已完成。
