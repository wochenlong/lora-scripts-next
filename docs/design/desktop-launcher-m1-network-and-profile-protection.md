# M1 网络策略与用户资料保护补充合同

本合同补充 #516 桌面启动器的 M1 实现。阶段进度只维护在 `docs/tasks/desktop-launcher-full-plan/00_总控目标索引.md`；下述代码能力与原生验收分别记录，不能由静态测试推导全部 M1 完成。

## 当前安装根的网络设置

网络设置位于安装根的 `config/network.local.json`，与用户资料、版本目录和依赖环境分开。读取不建立目录，写入需要工作区租约，并在写入之前验证代理、实际生效来源和 64 KiB 大小限制。无效设置不能覆盖原文件或预先建立工作区。

Rust 与训练器现有 `mikazuki/networking/policy.py` 共用测试向量，保持以下语义：

| 模式 | 解析规则 |
| --- | --- |
| `auto`（自动） | 显式设置和环境变量优先，未指定的协议再按 `ALL_PROXY` 与系统代理补齐；显式空字符串禁用相应协议 |
| `system`（系统） | 使用 Windows 当前用户的代理设置，忽略传输代理环境变量 |
| `manual`（手动） | 明确指定 HTTP/HTTPS 代理；只填写一种时复用于另一种 |
| `direct`（直连） | 清除子进程中代理变量的不同大小写形式，明确直连 |

绕过规则支持域名及子域、通配符、端口、IP 网段和 `<local>`。localhost 与回环 IP 始终直连。PAC 仅提示未执行，不擅自运行脚本。显式代理连接失败直接报告错误，不回退直连。任务开始后冻结策略；修改设置用于后续任务。

Rust 请求显式关闭库的默认代理发现，采用冻结策略选择代理。固定 GUI 配方的 uv 仍在离线模式工作，资产由 Rust 下载器获取；兼容路径的 uv 使用同一策略。训练器子进程获得当前根的网络配置路径及原始代理输入记录，供既有 Python 下载、Git 和模型 worker 读取。原始输入与启动器注入值分开，避免从手动模式切回自动时把旧注入值当成操作者配置。

代理凭据只存在于本机设置、受控 IPC 与必需的子进程环境中。输入框遮挡其值，Debug、日志、操作事件与持久错误去除 URL 凭据和查询参数。脱敏验证使用合成凭据。设置不进入 Git、测试截图或公开报告。

共享解析向量、回环 HTTP 代理/重定向/失败不直连测试和原生设置验收分别证明其覆盖范围。网络正文预算与实际 TLS 线流量是不同计量；当前外部测试计量器的线流量回执不代替尚未完成的产品累计预算合同。

## 用户资料的流式内容保护

资料树与可修改环境的快照使用不同的资源限制。依赖环境及修复闭包仍受原先的单文件、整树、条目与持久状态大小约束；不再把 1 GiB 单文件、4 GiB 整树、5 万条的快照限制套在只读资料保护上。

新实例观察记录使用 `profiles_summary` 版本 1，保留根是否存在、节点数、文件数、总字节数和 SHA-256 内容承诺。每个文件仍逐字节读取和哈希；目录摘要按确定顺序编码名称、节点类型与子摘要，并使用明确的哈希域。文件大小、mtime 或文件身份不能替代内容哈希。

资料扫描使用固定缓冲，每块检查取消和截止时间。当前独立限额为单次扫描 900 秒、8 TiB、100 万节点、单目录 10 万项、深度 128、累计路径内存预算 256 MiB。达到限额拒绝本次变更并保留资料。Windows 读取句柄不共享写入与删除；目录读取前后核对枚举，扫描期间内容或路径变化不能被接纳为稳定基线。

每个实例记录只保存资料的固定大小摘要，避免把大量用户路径复制到每份 32 MiB 状态文件。资料摘要用于本次事务前后保护，正常启动不重新扫描全部资料。

## 旧实例与中断事务兼容

旧记录缺少 `profiles_summary` 时继续读取原 `profiles` 完整树。新记录不允许同时声明非空旧树与新摘要；未知摘要版本拒读。旧的 dirty/pending 事务在恢复完成前保持原树及原序列化摘要，不能在恢复中途改写快照合同。

新事务可以从旧的干净实例切入摘要合同，比较时将旧树转为同样的内容承诺。恢复成功后才保存新摘要。源码组件修复也使用同一资料摘要，但环境、Python、其他版本、状态和工具仍逐项保护。资料变化检测与旧事务恢复、安装器生成文件的信任和基础 Python 的共享引用修复是各自独立的验收项。
