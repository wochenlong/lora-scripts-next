# 数据集模块状态保持与编辑器恢复设计

## 1. 任务升级

本任务正式从“tag 翻译功能”升级为“数据集模块修改”。标签翻译是数据集编辑器状态保持的一部分，不能再单独修复。

用户提供的四张截图记录了复现路径：在标签编辑器中打开数据集后进入侧边栏“任务”，再返回“数据集/标签编辑”，编辑器显示为未加载状态，原数据集、当前图片和侧边栏状态全部消失。

## 2. 目标行为

- 返回数据集模块时自动恢复上一次打开的数据集。
- 保留上一次选中的图片、caption 编辑草稿、批量选择、筛选条件、分页和右侧面板状态。
- 保留中文释义显示开关、翻译 provider 和已经成功的翻译结果。
- 切换到任务、设置或训练模块只停止当前页面监听，不删除 Dataset Editor 的资源缓存和编辑草稿。
- 浏览器刷新后至少恢复上次数据集路径、当前图片、未保存 caption 草稿和翻译显示偏好；数据集内容通过重新扫描恢复。
- 数据集不存在或重新扫描失败时保留恢复信息并显示错误，不能静默清空编辑器状态。
- 用户主动加载另一个数据集时，明确切换编辑上下文；旧数据集草稿按数据集根路径隔离，不能串到新数据集。

## 3. 状态边界

| 状态 | 保留范围 | 存储方式 |
| --- | --- | --- |
| 当前数据集路径、根目录 | 跨路由、刷新 | 版本化 localStorage |
| 当前图片、选择和筛选 | 跨路由；刷新尽力恢复 | 应用内 session，关键字段持久化 |
| caption 草稿 | 按 `datasetRoot + relativePath` 隔离 | 版本化 localStorage，成功保存后删除对应草稿 |
| 已扫描图片/标签列表 | 当前应用会话 | 模块级资源状态；刷新后重新 scan |
| 标签翻译结果 | 跨页面和数据集共享，按 provider/locale/tag 隔离 | 应用级缓存，后续接入后端持久缓存 |
| 弹窗、loading、请求代次 | 当前组件/请求 | 不持久化；卸载时取消展示订阅 |

## 4. 实现边界

- 新增 Dataset Editor session 状态模块，避免依赖父路由的 `KeepAlive`。
- `DatasetPage` 内部的页签 `KeepAlive` 继续保留；跨侧边栏路由由 session 状态恢复。
- `choose()` 只切换当前图片和 caption 草稿，不调用翻译缓存清空。
- `scan()` 在恢复已有 session 时优先选择上次图片，并把未保存草稿恢复到当前编辑字段；服务器返回值始终保留为草稿比较基线。用户显式输入新路径时创建新的 dataset scope。
- 翻译 composable 改为应用级缓存，组件卸载不清空成功结果；请求代次只阻止旧结果更新当前视图。
- 不把图片二进制、完整图片列表或 API Key 写入 localStorage。
- 所有缓存和草稿操作按数据集根路径或资源键隔离，禁止无范围全局清理。

## 5. 验收用例

1. 打开数据集，选择第二张图片，修改 caption 但不保存，显示中文释义；进入任务页后返回，数据集、图片、草稿和释义仍在。
2. 在数据集页签之间切换，状态不丢失；切换到另一个数据集后，两个数据集的草稿互不污染。
3. 刷新浏览器，自动恢复上次数据集路径并重新扫描，当前图片和草稿恢复；扫描失败时显示错误且保留路径。
4. 延迟旧翻译请求，在切换图片和离开/返回页面后完成，不能覆盖当前图片的 caption 或加载状态。
5. 显式保存后，对应草稿被删除；重新扫描得到服务器已保存 caption。
6. 原始 caption 文件、训练输入和导出内容不包含中文释义。
