## 不需要重新讨论的已验证基础

继续使用 Tauri 2 + Vue 3 + Rust，保持三页、900×600、灰阶工程风。发布身份使用渠道和完整提交；源码、环境、用户 profile 分离；只有实际健康后才标健康；保护当前与回退版本；修改资料前必须有明确迁移合同；不按端口或进程名杀其他程序。

如果希望改变这些基础，先记录原因与影响，并回到设计变更审核，不能在实现时默默替换。

## 本轮已发现、设计阶段必须解决的事项

- Anima Fast 对解析后路径的限制与受管 `extensions` 联接冲突，多引擎 `.python` 路径也尚未稳定；需先做 RuntimeLayout，不能直接套现有 API。
- 部分现有 status/preflight 有写入，某些 repair 实际强制重装；Kohya 还有修改 GUI 主环境的兼容路径。新合同必须区分只读、探测、修复并明确环境所有者，不能只加按钮包装旧路由。
- 长操作当前持 Engine 锁；新增取消必须走独立控制通道，否则按钮会排队等待操作结束。
- 旧 journal 不具备续传 checkpoint；新操作记录与旧结构分版本兼容，未知格式继续拒绝写入。
- 远端最新列表不能决定本地历史是否存在；否则离线、下架会破坏回退。
- Windows venv 不能默认靠 staging 后重命名发布；自更新也不能只保留旧 EXE 而不验证状态是否仍可读。
