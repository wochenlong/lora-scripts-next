## 结论

参考项目对本项目的价值是局部的，主要保留两项：

1. 自然语言打标页面把语言、长度、试标、批量生成、覆盖备份和失败重试分开，用户可以先验证少量样本再处理整个数据集。
2. 中文和英文使用两套完整提示词。英文选择时，整段指令和系统提示词都使用英文；中文选择时同理。不能只替换一个语言占位符。

它不作为后端架构标杆。它缺少正文实际语言校验、自然语言整句翻译、统一打标/翻译 LLM 管理、提示词 revision 任务冻结和与编辑器的完整集成。它的关键词词典翻译不能承担 Caption 翻译。

## 已锁定的设计修改

- 英文是自然语言打标默认语言，面向主要训练使用场景。
- 后端内置模板按 `en`、`zh-CN`、`zh-TW`、`ja` 独立保存；没有 prompt 时按请求语言选择完整模板。
- 前端内置模板与后端语义一致，并保留用户自定义模板；语言和详略统一由预设选择；切换前确认未保存修改，不静默覆盖用户草稿。
- 描述详略提供“简短（1–2句）/详细（3–5句）”。这是完整内置模板选择，用户修改后的详略由提示词内容决定；选择其他预设先确认。字数上限与生成 token 上限独立，句数由模型遵从，不做机械截句。
- 默认模板明确要求严格 JSON、目标语言、可见事实和禁止臆测；响应仍必须通过结构和实际语言校验。
- 繁体和日文已有语言选项分别使用完整对应模板，避免把英文模板的固定 en 或中文模板的固定 zh-CN 发送给其他语言请求。
- 单图试标和批量任务继续共用同一快照和执行链路；试标不写回。
- Dataset Editor 中自然语言按整段原文编辑，中文译文只读展示；中文原文直接短路，不调用模型；Tag 清理、排序、拖拽和批量 Tag 操作保持禁用。
- 翻译和打标继续共用 LLM 管理层；翻译只要求 `text`，打标必须要求 `vision`。

## 不采纳的参考设计

- 不复制参考项目的单一独立描述服务配置。
- 不复制默认中文、不提供正文语言校验的行为。
- 不把 Caption 翻译实现成关键词字典转换。
- 不新增独立进程、Agent 接口、sidecar 或组合 Tag+Caption 入口。

## 验收重点

自动测试验证默认请求在英文和中文下分别收到完整对应语言模板；英文响应含中文字符必须拒绝，中文响应无汉字必须拒绝。前端验证预设语言切换、内置模板恢复和用户草稿保护。人工测试重点是英文打标、中文打标、预览不写盘、标签编辑页原文显示、自然语言整句译文、中文原文免请求和自然语言 Tag 操作禁用。

本次修改不改变 Issue #409 已冻结的模型优先、能力校验、远程优先、本地显式兜底、任务持久化和安全写回边界。


## 2026-10-10 预设统一控制（取代独立语言/详略选项）

用户授权：移除重复的“输出语言”，让提示词预设成为语言和输出格式总控。本次一并将详略入口收敛为预设中的“详细/简短”，避免多个入口描述同一份模板。

- 默认内置英文详细预设；选择预设一次应用完整 user/system prompt、语言与最大字符数。内置中英、繁体、日文各有详细/简短模板。
- 页面仅显示只读预设语言与纯文本 `.txt` 落盘格式；内部严格 JSON 响应协议仍由后端校验，不引入 JSON 文件或组合打标。
- 自定义模板继承当前预设的语言；先选择对应语言的基底再编辑、保存或另存。已有用户默认预设保持，未保存修改在切换时仍需确认。
- 切换模型不再静默换语言或模板。模型不支持预设语言时明确提示、禁用预览和批量提交；用户可选兼容预设或模型。
- 试标/批量从同一份预设草稿派生请求；重试继续使用既有冻结快照。后端 language 字段保留作为校验与 API 兼容契约，没有第二个用户语言控制来源。
