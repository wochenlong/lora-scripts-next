# 标签翻译 V5 Review 与加固设计书

更新时间：2026-10-03（Asia/Shanghai）  
审查范围：`feat/tag-translation` 当前提交 `cbf3ea7` 及隔离运行环境

## Review 结论

### P0：新增草稿标签没有进入筛选索引

实测步骤：在 Dataset Editor 当前图片中新增 `new_review_tag`，不保存文件，立即打开“筛选”。标签编辑器中能看到该 tag，但筛选标签列表中没有它。原因是 `addCaptionTag()` 只修改 `caption`，`tags` 是扫描结果快照，筛选面板的 `visibleTagList` 只基于 `tags` 计算；未保存草稿没有被合并进筛选索引。

影响：用户无法立即用筛选定位刚添加的标签；即使把标签显示到列表后，如果筛选仍使用服务端快照，勾选该 tag 也不会命中当前草稿图片。

修复方向：建立“服务端已保存标签 + 当前会话草稿标签”的统一 tag 索引和可筛选 items；新增、删除、原文编辑、切图和批量编辑后都重新计算草稿索引。草稿标签可被显示、勾选和命中筛选，但不写入服务器，直到用户点击保存。

### P0：新增标签不会自动补译

实测步骤：中文释义开关保持开启，新增 `new_review_tag` 后，进度仍为 `2/2`，新增 tag 没有翻译。原因是翻译只在开关、provider、scan 时触发，caption 变化没有触发“只解析新增 tag”的请求。

修复方向：监听规范化后的全数据集 tag 集合签名，使用短 debounce；集合变化时调用现有缓存感知的 `resolve`，只请求未命中的 tag，保留英文原文和现有翻译，避免重新翻译整个数据集。

### P1：远程 LLM 配置卡片缺少折叠和清晰的选择状态

当前所有远程 profile 的 endpoint、模型和 Key 始终展开，多个接口时弹窗高度和滚动成本快速增加。当前已有 active profile 逻辑，但选择和编辑状态混在同一张展开卡片中，用户难以确认“当前使用哪个接口”。

修复方向：每个 profile 使用可控的折叠卡片；新增 profile 自动展开，active profile 默认展开，其余默认折叠；折叠标题保留名称、模型、当前启用标记和展开按钮。启用仍保持全局单选，删除 active 后自动迁移到首个 profile。

### P1：本地服务停止后的引导不足

当前停止本地服务后，保存按钮正确禁用，但用户只看到 disabled 状态，没有告诉用户应该切换到远程接口或重新启动本地服务。若远程 profile 也没有 API Key，用户选择“LLM · 本地或 API”后只能得到请求失败。

修复方向：

- 本地模式未 running 时，在设置卡片显示明确警告和“启动本地服务”“切换远程接口”动作。
- 远程 profile 未配置 Key（或不允许无 Key 的 loopback endpoint）时显示“先配置接口”的提示，并提供“打开翻译设置”动作。
- Dataset Editor 选择 `LLM · 本地或 API` 时，先读取已保存配置和本地运行状态；不可用时显示 warning 并打开设置弹窗，不发起必然失败的翻译请求。
- 后端继续保留 409 保护，前端提示与后端状态保持一致。

### P1：取消设置后草稿状态可能污染后续翻译

当前设置弹窗直接编辑 `llmProfiles`、`activeRemoteId` 和 `llmMode`，点击取消只关闭弹窗，不恢复上次已保存配置。用户取消后，前端可能认为已经选择了另一个 profile 或本地模式，但后端仍使用旧配置，造成模式切换不一致。

修复方向：打开弹窗时读取并保存 committed snapshot；取消、关闭或保存失败时恢复 snapshot；保存成功后更新 snapshot。所有翻译请求只依据已保存配置，草稿只用于弹窗编辑。

### P1：多模式切换缺少请求边界和可见反馈

前端 generation 机制可以阻止旧响应覆盖新状态，但切换 provider 或 profile 时没有统一的“正在切换/已清空旧结果”反馈；后端 profile revision 虽能隔离缓存，用户仍可能看到旧 provider 的中文释义短暂残留。

修复方向：切换 provider 时取消当前请求、清理当前展示域的 loading/error，保留持久缓存但以新 provider 重新计算；进度显示当前 provider 和 `N/N`，错误提示给出可操作入口。

### P2：设置弹窗的配置验证前置不足

后端会验证 endpoint/model，但前端直到点击保存才发现空字段或无效地址。远程配置卡片应在卡片级显示缺失字段，保存按钮可点击但给出具体字段提示；API Key 采用已保存掩码时不能被空输入覆盖。

### P2：可观测性和回归覆盖仍可增强

目前有后端专项测试和基础前端测试，但缺少以下回归：取消设置恢复草稿、远程 profile 折叠/单选、停止本地后的提示、新增草稿 tag 同步到筛选和自动补译、多模式切换中旧响应丢弃。

## V5 验收目标

1. 用户新增、删除或编辑 tag 后，筛选列表和中文释义在当前会话内立即一致。
2. 远程接口配置在多 profile 场景下可折叠、可单选、可取消编辑，且不会污染已保存模式。
3. 本地停止、远程缺配置和 LLM provider 不可用时都有明确的下一步操作。
4. Danbooru、MyMemory、远程 LLM、本地 LLM 和自动回退切换时，旧请求、旧缓存和展示状态不串线。
5. 在全新隔离目录中只使用已有依赖启动项目，完成所有翻译设置按钮、模式切换、筛选、草稿、缓存和刷新验收。
