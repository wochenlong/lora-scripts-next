# M1 固定环境实例与 Windows 路径兼容补充

本说明记录 #516 实施中发现的技术修订，不替代[完整任务书总控](../tasks/desktop-launcher-full-plan/00_总控目标索引.md)。功能分支为 `feat/desktop-launcher`，阶段仍为 M1；本说明不表示阶段验收通过。

## 问题与实际证据

2026-10-29，在中文空格目录中的原生安装已实际完成固定 Python 准备和源码发布，但 uv 0.11.16 安装依赖时无法持久化 282 字符的 `tensorboard_data_server` 元数据路径。宿主 `LongPathsEnabled=0`；未更改系统设置。独立实验确认 uv 会归一化 `\\?\` 输入，当前卷没有可用短文件名；跳过安装器元数据后，CPython 仍可能把真实包当作 namespace，因此这些方式不能作为修复。

固定 81 个 wheel 映射核算中，最长原文件的环境相对路径为 152 个 UTF-16 单位，最长安装器元数据为 73。旧环境布局本身再占约 100 个字符，使合法安装根也容易触发限制。原始 ZIP 文件能解压不代表 Python 随后能读取、导入或加载 DLL。

证据位于外部本 run 的 `M1/operations/managed-native-resume2-20261029-022504Z/`、`long-path-probe-20261029-023050Z/`、`long-path-metadata-probe-20261029-0235Z/` 和 `wheel-path-inventory-20261029-0241Z/`。原失败目录与 dirty 实例保持原状。

## 持久身份和物理路径

发布身份继续使用完整源码提交、发布配方摘要、实例 ID 和 generation，不依赖目录缩写判断来源。`EnvironmentBinding` 与 `InstanceState` 增加可选整数 `storage_version`：

| 值 | 物理环境目录 | 读取与创建规则 |
| --- | --- | --- |
| `0`，字段缺省 | `environments/<完整release-id>/instances/<instance-id>/gui` | 保持已有记录语义；零值序列化省略，旧记录不被重新解释 |
| `1` | `e/<instance-id>` | 新实例采用；ID 严格为 `g` 加 16 位小写十六进制，目录通过原子创建拒绝碰撞 |

所有路径通过同一 `model::environment_path` 派生，不从状态文件接受任意相对路径。短 ID 只缩短物理位置，不能替代完整发布身份和已验证内容。绑定和实例的存储版本必须相符，同 ID 同时占用两个命名空间、短实例共绑不同发布、越界和未知存储版本均拒绝。

两个命名空间都进入非目标事务保护，排除当前目标实例。已有旧 dirty 事务缺少 `e` 保护基线时，只在 `e` 不存在或为空时按原合同恢复；已有短实例则拒绝追认，保留 dirty 和快照。

## 安装预检与验证边界

在建立工作区和下载前，固定 GUI 配方先保守核对新环境绝对目录加最长可信原文件是否超过 259 个 UTF-16 单位。超限时给出明确路径错误，保留现有文件，要求用户选择更短目录。此预检不修改 Windows 注册表，不省略元数据，不降低文件校验。更换固定配方或映射规则时必须重新计算路径预算。

本次短目录实现与前端、文件校验、恢复机制均需由新构建重新实测。已有成功的配方独立 venv、旧 EXE 或浅层关键导入不能证明新实例整链通过。基础 Python 自带深层测试数据仍有独立长路径适用限制；当前未宣称任意深度安装根或 Python 所有测试数据路径均受支持。

## 保护要求

源码、环境和用户资料继续独立。精准修复仍使用可信 wheel 推导的文件闭包、独立快照、持久 dirty/generation 和 intent；基础 Python 使用固定归档推导的完整文件清单，在执行解释器前校验。安装器生成脚本明确保留内容验证边界；未验证的后生字节码不作为可信执行内容。

大型 profiles 的事务扫描仍会受到原安全限额约束，当前保持超限拒绝。不能以 size、mtime 或 file ID 代替资料内容哈希并宣称字节不变；可用性改进和 M1 相关故障矩阵仍待完成。
