# 自然语言打标：兼容性与迁移说明

## 用户可见行为

- Tag 和自然语言 Caption 默认递归扫描子目录。`batch_input_recursive` 的后端默认值从 `false` 改为 `true`；API 调用者仍可显式传 `false`，界面使用默认递归。
- 最新 dev 的 Tag 任务预设（角色、风格、通用）保留，预设选择模型与阈值；自然语言使用独立的提示词预设控制输出语言和格式。Tag 的模型恢复按钮恢复当前任务预设。
- 旧数据集若只有 TXT 而无格式来源记录，会按 `unknown` 保护原文。清理、排序、去重等 Tag 批量操作可能返回 HTTP 409；先在编辑页确认标注格式后再执行。自然语言继续使用原文编辑和整句翻译，不能通过逗号拆分推断 Tag 来源。
- 正文翻译需要 Python 3.10 或更新的受支持运行时。取消只终止当前显示请求，不修改数据集 TXT；迟到译文不会回填翻译缓存。

## 第三方脚本迁移

`PUT /api/tag-translation/config` 现在要求 `revision`，以防多个页面互相覆盖配置。先 `GET /api/tag-translation/config` 取得最新 `data.revision`，修改需要的字段后把该 revision 一起提交。省略或提交过期 revision 会返回 HTTP 409（`llm_config_conflict`）；重新读取、合并所需字段后重试，不应盲目覆写。

编辑 API 遇到 `unknown` 格式的 409 时，应提示用户确认 Tag/自然语言格式，或使用带哈希保护的原文编辑接口；不得为恢复批量操作而自动把任意句子判为 Tag。API 路径和数据结构见 [数据集打标 API](../api/dataset-tagging.md)。

## 数据目录与运维

原生 Tag 和 Caption 写入共用 SQLite 任务/来源记录，作为原子补偿、格式保护、冲突检测和回滚依据。数据目录必须可写；不能仅保留模型文件而把任务库设为只读。备份数据时应同时保留 TXT、任务库和来源记录；数据库不可用时应报告失败，不绕过保护直接写 TXT。

现有 Tag 生成结果及模型资产继续保留；共享 LLM 配置优先使用远程接口，本地模型为可选兜底。升级不要求重复下载本地模型。验证命令、解释器要求和历史验收边界见 [验证说明](../caption-validation.md)。
