# AI Toolkit 接入协作者简报

更新日期：2026-10-02

## 1. 唯一追踪入口

AI Toolkit 的产品接入统一在 GitHub Issue [#284](https://github.com/wochenlong/lora-scripts-next/issues/284) 跟踪。

- 新需求、范围变更、验收记录和阻塞问题都回复 #284。
- 不再为 Klein、Anima、SDXL、Krea 2 或 Qwen Image 单独拆出平行的 AI Toolkit 总 Issue。
- 早期 PR #307 仅作为参考实现，不是当前合并目标；不要以 #307 的旧范围替代 #284 的最新范围。

## 2. 当前产品定位

Next Trainer 是多引擎训练工作台。AI Toolkit 是新增的可选训练引擎，与 Kohya、Anima Fast、Musubi、DiffSynth 并列：

- 不替换现有引擎。
- 不把 AI Toolkit 设为默认引擎。
- 不要求默认整合包预装 AI Toolkit。
- 使用统一的引擎安装、审计、就绪、异常和卸载生命周期。
- 前端行为、任务监控、预览图和数据集入口应与其他引擎保持一致。

首版应覆盖前端和后端，不接受“只有菜单入口”或“只有后端能跑”的半接入状态。

## 3. 首批模型范围

| 模型 / 系列 | 首版目标 | 说明 |
| --- | --- | --- |
| SDXL | LoRA，文生图 | 与现有 Kohya 能力并存，使用 Toolkit 原生配置 |
| Flux | LoRA，文生图 | 以 AI Toolkit 实际支持的模型变体为准，先明确底模和文本编码器要求 |
| Klein | LoRA，文生图和图像编辑 | 4B / 9B、base / non-base 按上游能力逐项验收 |
| Krea 2 | LoRA，文生图 | 与 Musubi 并存，Toolkit 是平行训练路径 |
| Anima | LoRA，文生图 | 与 Kohya / Anima Fast 并存 |
| Qwen Image 2.1 | LoRA，文生图和图像编辑 | 复用现有 DiffSynth 的数据集、参考图、预览和任务监控经验；以 Toolkit 实际能力为准 |

首版不默认承诺：

- AI Toolkit 全量微调。
- 所有上游模型变体、量化方式或高级训练模式。
- 自动下载或自动转换所有底模。
- 将 Klein 接入 Musubi。

每个模型都必须有明确的：模型来源、目录结构、文本编码器 / VAE 要求、显存边界、配置生成方式、最小训练验收和产物格式。

## 4. 必须遵守的引擎接入协议

### 4.1 引擎隔离

AI Toolkit 使用独立运行环境，不污染 GUI、Kohya、Musubi 或其他引擎环境。

必须提供：

- manifest / 引擎能力声明；
- 独立 venv 或等价运行时；
- 安装、审计、就绪、异常、重新安装和卸载；
- 解释器、模块、`sys.path` 和运行目录检查；
- 训练启动前的 preflight；
- 失败状态、日志和任务元数据。

统一链路：

```text
GATE -> ADAPT -> PREFLIGHT -> DUMP -> LAUNCH
```

### 4.2 配置与数据集

- 工作台字段通过 adapter 转换为 AI Toolkit 原生 YAML 或等价 job config。
- 不让前端直接拼接 AI Toolkit 命令。
- 数据集使用项目已有数据集契约；文生图使用 `train_data_dir`，图像编辑使用 `train_data_dir + control_data_dirs[]` 或已确认的等价结构。
- 训练、打标、标签编辑共用同一数据集路径语义，不复制一套私有目录规则。
- 导入配置必须保留可识别字段；无法安全转换时明确报错或警告，不静默丢字段。

### 4.3 模型路径选择（前端）

模型路径区域参考现有 DiffSynth / Qwen 页面，不使用一个含义不清的“模型路径”输入框承载所有格式。建议采用以下层级：

1. **训练模型**：显示当前训练类型，只读或由训练类型选择器控制。
2. **模型输入模式**：根据 AI Toolkit 模型能力提供明确选项，例如模型仓库、标准模型目录、单文件或 ComfyUI 文件 / 目录。
3. **条件路径字段**：输入模式改变后，只显示当前模式需要的字段，并在字段下说明期望格式、模型组件和是否允许目录。
4. **路径操作**：每个路径字段提供服务端“浏览”和重新读取 / 刷新动作；浏览器端不假设模型在本机。

参考 DiffSynth 的交互形式：

- `model_input_mode` 负责说明“这组路径是什么”；
- `dit_path`、`text_encoder_path`、`vae_path` 等字段跟随模式显示；
- 每个字段有必填标记、格式提示、路径输入、浏览按钮和刷新按钮；
- 目录、单文件、仓库 ID 必须在 UI 和 adapter 中区分，不能只靠后缀猜测；
- 切换模式不应静默删除用户已经填写的路径；应保留草稿，提交时只序列化当前模式有效字段；
- 导入旧配置时尽量保留原始路径，无法判断格式时要求用户确认，不自动转换。

AI Toolkit 首批每种模型的路径模式必须在模型能力声明中注册，由 schema 驱动前端；不要在 Vue 页面中为每个模型写独立分支。

### 4.4 任务与观测

- 训练必须通过统一任务队列和 `/api/run` 进入。
- 日志、进度、Loss、TensorBoard 和训练预览必须接入现有任务系统。
- 预览图路径、Loss 标签和输出目录必须写入任务 metadata。
- AI Toolkit 的 YAML、进度条和 sample 命名与 Kohya 不同，必须在引擎适配层解析，不能修改共享解析器来迁就单一引擎。
- GUI 训练页、任务页和设置页保持现有交互层级；新引擎特殊字段放进 schema，不复制整套页面。

## 5. 底模格式与额外空间

这是 AI Toolkit 接入的重点设计问题。

部分老模型不接受 ComfyUI 文件格式，而现有模型资产或用户常见下载可能是 Comfy 格式。不能默认把每份模型都无提示地复制或转换，因为会：

- 占用额外磁盘空间；
- 产生两份难以区分的权重；
- 增加转换失败、精度和版本兼容风险；
- 让用户误以为原文件已被修改。

请在 #284 中提出并比较至少以下方案：

1. **显式转换缓存**：原文件只读，按模型哈希和 Toolkit 版本生成转换缓存；可清理、可复用、显示占用空间。
2. **引用 / 软链接 / 适配层**：只有格式兼容时使用，不能把路径伪装成已转换格式。
3. **用户预先转换**：训练前检查格式并给出明确命令或 GUI 入口，适合不希望自动占空间的用户。
4. **直接支持两种格式**：仅在上游确认安全且有真实训练验证时采用。

推荐优先评估方案 1，并明确缓存生命周期；但最终以实际模型矩阵、转换工具许可证、显存 / 加载行为和 Windows 文件系统表现为准。必须记录：

- 原文件路径与格式；
- 转换缓存路径、来源哈希和工具版本；
- 缓存占用和清理入口；
- 转换失败时的可读错误；
- 训练配置实际使用的文件。

禁止把转换逻辑散落在各模型 adapter 中，应该抽象成模型资产层能力。

## 6. 哪些可以改，哪些不能改

### 可以改

- `mikazuki/engines/ai_toolkit/` 内的新引擎实现；
- AI Toolkit 专属 manifest、adapter、preflight、launcher、installer、runtime；
- 引擎 schema、模型能力声明和对应中英文文案；
- 训练页 schema 字段注册、条件显示和配置序列化；
- 任务 metadata、进度 / Loss / preview 的引擎分支；
- 模型资产层中通用且可复用的格式检测 / 转换缓存；
- AI Toolkit 专属测试、文档和验收脚本。

### 不要直接改

- 不要修改 Kohya、Anima Fast、Musubi、DiffSynth 的默认行为来迁就 Toolkit。
- 不要把 AI Toolkit 依赖加入主 GUI 或其他引擎的 requirements。
- 不要把 Toolkit 设成全局默认或强制预装。
- 不要修改数据集路径契约、图像编辑数据集契约或已有训练输出语义。
- 不要让 AI Toolkit 直接绕过任务队列、preflight、统一日志和取消链路。
- 不要直接重写共享 `api.py`、任务监控或解析器；若确有必要，采用明确的 `backend == "ai-toolkit"` 分支并补回归测试。
- 不要手工编辑 `frontend/dist`；由前端源码构建生成，除非发布流程明确要求同步产物。
- 不要删除或关闭 #284 以外的历史 Issue 来表示完成。
- 不要把 #307 的代码整体直接合并；先按本简报和 #284 的最新范围取舍。

## 7. 前端复用方向

前端应和其他引擎一致：

- 训练类型、引擎、目标的选择层级不变；
- 通过 schema 动态显示模型字段；
- 设置 → 训练引擎统一显示安装 / 审计 / 就绪 / 异常；
- 训练预览图复用现有 `PreviewSampleField` 和任务页预览能力；
- 图像编辑数据集复用 DiffSynth 已完成的目标图 + 参考图交互；
- 复用现有路径选择、数据集根目录、TOML / 配置导入导出和任务草稿；
- AI Toolkit 特有的 YAML 或模型资产提示应放在专属字段说明中，不改变全局 UI 风格。

参考实现：

- 早期 AI Toolkit / Klein：PR [#307](https://github.com/wochenlong/lora-scripts-next/pull/307)，仅作参考。
- DiffSynth / Qwen 图像编辑：仓库现有 `mikazuki/engines/diffsynth/`、训练 schema、`PreviewSampleField` 和数据集工作区。
- 引擎生命周期：[训练引擎管理协议](../design/training-engine-management.md)。

## 8. 最小验收门槛

每个首批模型至少完成：

1. 可发现并安装独立引擎环境；
2. 审计通过，且不污染其他引擎；
3. GUI 能生成正确 Toolkit 配置；
4. preflight 能拦截缺失模型、格式错误和路径越界；
5. 能提交任务、显示日志和进度；
6. 能看到 Loss / 预览图；
7. 能成功完成最小真实训练并保存 LoRA；
8. 重启后任务状态和引擎状态可恢复；
9. 至少验证 Windows 路径、空格路径和现有数据集目录；
10. 记录显存、模型格式、转换缓存大小和已知限制。

可以分阶段合并，但每次合并必须说明覆盖了哪些模型和验收项，不能用“AI Toolkit 已接入”概括未完成能力。
