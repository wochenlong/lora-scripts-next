# Windows 桌面启动器安装与恢复说明

本文适用于 Next Trainer 桌面启动器开发候选。请同时保存包内的 `build-manifest.json`、哈希清单、`LICENSE`、`NOTICE.md` 和 `LICENSES`，据此确认候选来源和已验证范围。正式维护者签名身份与生产更新渠道尚未配置；开发候选的生成不等于公开发布或系统验收完成。

## 安装器与便携包

Windows x64 用户可以选择 NSIS 安装器或便携包。安装器优先安装到当前用户可写位置；运行时工作区应选磁盘空间足够、路径清楚的独立目录。首次安装选择空目录，启动器会创建归属标记并保存版本、环境与用户资料。不要把已有整合包、模型目录或其他软件目录直接作为新工作区。

便携包应完整解压后运行主启动器 EXE，保留旁边的 `next-trainer-updater.exe`、说明与许可文件。便携指程序文件可整体移动；已经建立的 Python 环境仍依赖固定安装路径。移动工作区时不要直接搬动旧 venv，应由正式安装/重建入口生成新环境。

启动器壳和独立更新 helper 不需要系统 Python 或系统 uv。训练器、各训练引擎使用启动器管理的独立环境；安装前会展示所需来源、下载大小和操作计划。四个指定引擎为 Kohya、Anima Fast、AI Toolkit、DiffSynth。

## WebView2 组件

界面依赖 Microsoft Edge WebView2 Runtime。安装器配置使用 Microsoft 的在线 bootstrapper（引导安装程序），网络和系统条件允许时按当前用户安装。缺少组件、下载失败或权限不足时，请保存安装器日志，通过 [Microsoft WebView2 官方下载页](https://developer.microsoft.com/microsoft-edge/webview2/) 获取适合当前机器的 Evergreen Runtime；离线机器使用官方独立安装包。不要用来历不明的组件替代。

本轮开发机已有 WebView2。真正缺 WebView2、干净 Windows 与非管理员安装/卸载专项需要 M6 的对应机器条件验证，尚不能由新建目录或清空 PATH 替代。没有运行的专项会在交付清单明确标注 `not-run` 或 `blocked`。

## 首次使用与资料保存

在启动页选新工作区并安装训练器；版本页管理 main/dev 对应的固定发布；环境页查看或修复独立 GUI 与引擎环境。只在启动器判定可用后启动训练器。下载或安装失败时先保留失败日志与事务目录，按界面提供的诊断、精准修复或恢复入口处理。

用户资料位于 `profiles/<稳定ID>/`。设置、预设和任务归档按资料协议保存；模型和数据集通常使用外部绝对路径引用。版本源码位于 `releases/`，独立环境和控制状态由启动器分别管理。删除版本应通过版本页预览，当前版本、回退版本和共享资料会受到保护。

安装训练引擎时进入桌面“环境管理”，选择目标引擎，预览独立安装或精准修复并确认执行。支持新运行协议的训练器服务可以继续运行；只有目标引擎正在训练、被占用或已有变更时才限制修改。只读检查和计划预览仍可使用。主程序本体修复和切版本仍需先停止服务。旧训练器需在版本页安装本包最新固定发布才支持新协议，更新桌面程序不会自动改写旧训练器源码。

导入旧安装时先执行只读扫描与预览，再显式复制到新的 profile。源安装、旧 venv 和外部模型/数据集不会被接管或删除；含凭据的设置文件默认排除。当前支持 JSON 设置/预设/归档中的已知路径转换；TOML、YAML、Python 和未知插件配置会列为“不支持项”并保留源文件。请审核这份列表，再决定是否继续导入。

新 profile 的复制成功不会自动激活，也不会继承健康状态。先完成独立入口验证，再显式选择完整的“训练器发布 + profile + 环境实例”组合。回退保留上一健康组合；其环境实例或代次已经改变时，应先用正式环境回退入口恢复匹配实例，再选择该组合。

## 诊断与中断恢复

保存界面错误、最近操作 ID、版本 ID、包的 SHA256 和相应事务目录。诊断材料一般位于工作区 `state/`、`backups/`、`updates/shell/` 及引擎状态目录。分享日志前核对代理地址、访问令牌、个人路径和训练资料，避免公开秘密。不要把本机控制文件原件直接贴到公开 issue。

安装/修复/导入过程中断后，优先使用对应恢复入口。它会核对来源、实例代次、工作区锁和原字节快照。遇到未知 schema、损坏快照或无法证明归属的文件时，启动器会保留现场并拒绝覆盖。不要删除唯一失败现场、手工修改 `dirty` 或 `validated_generation` 来强行启用环境。

独立壳更新与训练器版本更新是两项操作。当前生产壳签名资产尚未配置，生产自更新默认不可用；开发验收的同包自复制仅限显式沙盒，不能替换任意安装目录的程序。helper 在原壳退出后持同一工作区锁，备份控制状态原字节，再试运行新壳。试运行只显示恢复界面并确认渲染与恢复入口，不启动训练、修复或资料迁移。失败会尝试恢复；恢复材料损坏时继续保留恢复模式，不声称已成功回旧壳。

## 卸载与重新安装

卸载程序文件前停止训练器、引擎进程与启动器，保存当前工作区路径。卸载壳应保留用户选择的工作区与 `profiles`；便携包可在程序完全退出后移除程序文件。不要把删除工作区、模型或数据集当作常规卸载步骤。

重新安装后选择原来的正式工作区，先查看诊断结果再恢复运行。若旧工作区 schema 与新壳不兼容，应保留原件和原壳，按明确的迁移/恢复入口处理。需要彻底清理资料时，先自行备份并核对实际目录，清理属于单独操作。

## 验证边界与许可

M1–M5 的编译和小夹具结果属于施工检查。最终同包从零安装、资料导入、壳更新与恢复等实际结果以 M6 交付记录为准。本机资源不满足固定 GPU 配方，用户已决定跳过真实 GPU/训练测试；四引擎仅做冒烟，不能据此声称真实训练或显存适配已验证。

包内应分别记录 catalog 元数据签名、Windows 代码签名和文件哈希。哈希只用于核对文件身份，测试签名只用于固定沙盒，二者都不能冒充维护者生产签名。源代码受仓库 `LICENSE`（AGPL-3.0）约束，第三方组件遵循各自许可；再分发时保留 `NOTICE.md` 的上游致谢，以及 `LICENSES` 中的依赖清单与原始声明。
