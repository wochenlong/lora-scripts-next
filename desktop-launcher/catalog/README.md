# 固定版本目录与下载来源

`releases.json` 随启动器嵌入，界面只能选择其中的版本 ID；运行时不接受任意下载 URL。`main` 和 `dev` 表示取样时的分支来源，版本号来自各归档内的 `VERSION`，不将 `main` 自动解释成稳定发布版。

2026-10-28 通过代理 `http://127.0.0.1:11809` 实时读取 `refs/heads/main`，得到 `0785419e7dc1a3058bd8710a9aa933fec0aabdee`；此前已核验的 `dev` 是 `9ca2de963122f34599e34e5ff382199de9188811`。两份 HTTPS 固定提交归档均已完整下载，SHA256、压缩字节和 ZIP 条目解压字节总数来自实际测量。GitHub 源码归档未提供独立校验清单，因此源码哈希的信任来源是本次固定提交 HTTPS 下载，不宣称独立官方签名认证。

uv 0.11.16 ZIP 哈希已与同 URL 后附 `.sha256` 的官方文件核对；`exe_sha256` 由该已校验 ZIP 内的 `uv.exe` 流式计算。Python 由已校验的 uv 按指定版本管理，并在准备后实际执行检查。

目录 schema、profile schema 和环境配方标识分别管理。两个取样提交均使用 `legacy-view-v1` 数据合同：不可变源码与共享 profile 分离，由启动器创建兼容运行视图。未知 schema 或未知数据合同拒绝变更。后续发布需更新固定提交和实测哈希，不能只改版本显示文字。
